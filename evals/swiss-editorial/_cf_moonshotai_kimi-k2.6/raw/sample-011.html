AHD Artificial Human Design
read the code

A framework for evaluating design systems with human judgment first.

The problem is not that AI generates design. The problem is that no one evaluates what it generates. AHD is a toolchain for running structured, repeatable critiques of design output—by humans, for humans, with machines only where they earn their place.

You write a brief in YAML. The compiler expands it into evaluation rules. A vision model scores the result against those rules. A human reviews the scores and overrides where the model is wrong. The override becomes training signal.

bash 
# Evaluate a live design against a brief, with vision critique
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
This runs local rules against remote models. The eval harness, linter, and compiler are yours. The frontier calls need your keys. The vision critique needs a multimodal model and a screenshot pipeline. Know what you are running.

What ships

  • Brief compiler — YAML to rule tree
  • 28-rule linter — typographic, spatial, and compositional constraints
  • Eval harness — batch runner with deterministic scoring
  • Vision-critic scaffold — OpenAI / Anthropic / local vision adapter
  • MCP server — Model Context Protocol for IDE integration
  • Editor plugins — Neovim, VS Code, Zed; source in repo, install from source
  • Eight tokens — base set for spatial, type, and color evaluation

What is gated

  • Live frontier-model calls — needs API keys
  • Live vision critique — needs multimodal key + screenshot pipeline
  • Standalone npm packages for the editor plugins — pending registry setup
  • Additional tokens — under review for quality bar
