AHD / Artificial Human Design
A framework for evaluating design with structured intent, not taste

The problem with most AI-generated design is not the tools. It is the absence of evaluability: no explicit brief, no lintable rules, no reproducible critique. AHD is a toolchain and protocol for describing what a design should do, generating candidates against that description, and scoring them with both automated and human review.

You already know the slop thesis. This is the response: a system that treats design as an engineering problem—specifiable, testable, versioned.

bash 
ahd eval-live swiss-editorial \
  --brief briefs/landing.yml \
  --models <specs> \
  --n 10

The one-liner runs the full pipeline: compile the brief, lint against 28 rules, generate candidates, score with vision critique, emit ranked results. Replace <specs> with your model configuration; the harness is model-agnostic.

What ships

  • Brief compiler — YAML/JSON schema with constraint resolution
  • 28-rule linter — typographic, spatial, and accessibility rules
  • Eval harness — batch runner with deterministic scoring
  • Vision-critic scaffold — multimodal pipeline ready for your keys
  • MCP server — Model Context Protocol integration
  • Editor plugins — VS Code, Zed; Vim via LSP bridge
  • Eight tokens — base vocabulary for design description

What is gated

  • Live frontier-model calls — needs API keys
  • Live vision critique — needs multimodal key + screenshot pipeline
  • Standalone npm packages for the editor plugins — packaging in progress
  • Additional tokens — vocabulary expansion, community validation pending
