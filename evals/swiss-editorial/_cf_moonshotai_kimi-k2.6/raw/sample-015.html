AHD

Artificial Human Design.
A framework for measuring what people mean when they say a design is "too AI."

The problem

"Looks AI-generated" is not feedback designers can act on. It collapses a dozen distinct failure modes — hierarchy, spacing, tone, cultural sensitivity, temporal context — into a single verdict that helps no one.

AHD provides a specific, auditable alternative. Write a brief. Compile it to a structured evaluation plan. Run it against models with consistent prompting. Score outputs against public, versioned rules. Review failures with a vision critic that references the same brief.

One command

Evaluations are reproducible and version-controlled. The full toolchain is open source.

bash 
$ ahd eval-live swiss-editorial \
  --brief briefs/landing.yml \
  --models <specs> \
  --n 10

# Outputs: scored.jsonl, failed_rules.json,
# screenshots/, and a summary markdown file.

What ships

  • in Brief compiler — YAML/JSON to structured eval plan
  • in 28-rule linter — versioned, auditable design rules
  • in Eval harness — parallel generation, consistent prompting
  • in Vision-critic scaffold — multimodal critique pipeline (local)
  • in MCP server — Model Context Protocol integration
  • in Editor plugins — VS Code, Zed (source in repo)
  • in Eight tokens — base design vocabulary

What is gated

  • out Live frontier-model calls — requires your own API keys
  • out Live vision critique — requires multimodal key + screenshot pipeline
  • out Standalone npm packages — for editor plugins; build from source today
  • out Additional tokens — expanded vocabulary pending
