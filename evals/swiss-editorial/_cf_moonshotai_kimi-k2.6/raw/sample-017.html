Artificial Human Design is a framework for evaluating design with the rigor of code review.

You have already seen the problem: interfaces that look plausible but collapse on contact with actual use. AHD does not sell a thesis. It provides briefs (structured design requirements), linters (rule-based evaluation), and harnesses (repeatable comparison of model outputs against human baselines). The goal is not to generate more design, but to generate design that can be accountable.

bash 
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

How it works

Briefs are YAML files that specify constraints: typography scale, spacing system, accessibility requirements, motion parameters. The linter checks outputs against 28 rules derived from WCAG, TSG, and established editorial design practice. The eval harness runs the same brief against multiple models and produces a diffable report. Vision critique adds a multimodal layer for cases where spatial relationships matter.

Everything is version-controlled and reproducible. The same brief run twice produces comparable output.

What ships

  • Brief compiler (.yml ↔ structured prompt with validation)
  • 28-rule linter (typography, color, layout, motion, accessibility)
  • Eval harness (batch execution, scoring, regression detection)
  • Vision-critic scaffold (multimodal evaluation pipeline, self-hosted)
  • MCP server (Model Context Protocol for IDE integration)
  • Editor plugins (VS Code, Zed, Vim—workspace-as-config)
  • Eight base tokens (design-system primitives, versioned)
All core tools run offline. No API keys required for linting, brief compilation, or local eval against cached outputs.

What is gated

  • Live frontier-model calls (requires API keys or local inference endpoint)
  • Live vision critique (requires multimodal key + screenshot pipeline)
  • Standalone npm packages for the editor plugins (pending registry setup)
  • Additional tokens (domain-specific sets, pending curation)
Gated items are documented and scriptable. Fork and replace the upstream dependency when needed.
