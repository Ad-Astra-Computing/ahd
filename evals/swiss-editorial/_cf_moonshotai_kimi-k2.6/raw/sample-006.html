AHD — Artificial Human Design

A framework for evaluating design, not generating it.

You have already seen what generative models do to design systems: undifferentiated spacing, hallucinated tokens, layouts that collapse under content stress. You do not need another sermon. AHD is a specification, linter, and evaluation harness for design that treats AI as a material constraint — one that must be measured, bounded, and held to the same rules as any other dependency.

bash 
$ ahd eval-live swiss-editorial \
  --brief briefs/landing.yml \
  --models <specs> \
  --n 10

What ships

  • Brief compiler (YAML/TOML to structured evaluation plan)
  • 28-rule linter (typography, spacing, color, motion, accessibility)
  • Eval harness (batch execution, result aggregation, regression diff)
  • Vision-critic scaffold (prompt templates, rubric format, scoring protocol)
  • MCP server (Model Context Protocol for IDE integration)
  • Editor plugins (VS Code, Zed, Helix language server bindings)
  • Eight tokens (baseline design vocabulary, CC-BY-4.0)

What is gated

  • Live frontier-model calls (needs API keys, rate-limit negotiation)
  • Live vision critique (needs multimodal key + screenshot pipeline)
  • Standalone npm packages for the editor plugins (pending registry)
  • Additional tokens (contributed, under review)
