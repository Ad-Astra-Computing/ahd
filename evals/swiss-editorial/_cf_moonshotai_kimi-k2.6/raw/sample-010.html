AHD / Artificial Human Design

A framework for evaluating generative design against explicit constraints

Most AI design tools optimize for output volume. AHD optimizes for constraint verification: turn a written brief into a reproducible eval, run it against candidate outputs, and know what failed and why. Built for teams who have already seen what unchecked generation produces.

bash 
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

What ships

  • Brief compiler (YAML/JSON → normalized eval spec)
  • 28-rule linter (typography, spacing, color, structure, motion)
  • Eval harness (batch runner with deterministic seeding)
  • Vision-critic scaffold (local pipeline for image-rule matching)
  • MCP server (Model Context Protocol for IDE integration)
  • Editor plugins (VS Code, Zed, NeoVim — install from source)
  • Eight open tokens (curated constraint sets for common patterns)

What is gated

  • Live frontier-model calls (needs API keys: OpenAI, Anthropic, or OpenRouter)
  • Live vision critique (needs multimodal key + screenshot pipeline setup)
  • Standalone npm packages for the editor plugins (pending registry verification)
  • Additional tokens beyond the base eight (community contributions reviewed)
Nothing in the gated list blocks local development. The linter, compiler, and harness run entirely offline. Gated features require external credentials or upstream processes outside our control.
