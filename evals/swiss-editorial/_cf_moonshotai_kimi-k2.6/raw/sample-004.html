AHD

v0.4.2

Artificial Human Design — a framework for evaluating generative output against human criteria

Problem

Generative tools produce more design artefacts than ever. The bottleneck is not generation speed; it is discrimination. Working designers still spend hours sifting, comparing, and explaining why one variant works and another does not.

AHD is a specification and toolchain for encoding that discrimination: turning taste into testable rules, and running those rules at scale against model output. You write the brief. The framework compiles it, lints it, and runs it through models you already have API access to.

One-liner

bash 
# evaluate 10 candidates against a brief using specified models
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

The eval-live command compiles the brief, instantiates the linter, runs the generation loop, and pipes output through the vision-critic scaffold if configured. Results are structured; you diff, not drift.

What ships

  • Brief compiler (YAML/JSON → internal IR)
  • 28-rule linter (typography, spacing, colour, motion, a11y checkpoints)
  • Eval harness (parallel execution, result collation, exit-code signalling)
  • Vision-critic scaffold (pluggable multimodal evaluation pipeline)
  • MCP server (Model Context Protocol adapter for editor integration)
  • Editor plugins (current: VS Code; Vim and Emacs in-repo, unpackaged)
  • Eight tokens (curated design vocabulary for seeding and constraint)

What is gated

  • Live frontier-model calls (needs your own API keys; no bundled inference)
  • Live vision critique (needs multimodal key + screenshot pipeline setup)
  • Standalone npm packages for the editor plugins (install from source today)
  • Additional tokens (domain-specific sets; CC-BY-4.0, separate download)
