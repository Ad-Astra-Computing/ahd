Artificial Human Design

Evaluation framework for design systems, not a generator.

You have already seen the problem: layouts that converge on the same 12-column grid, copy that reads like a press release, components that obey no constraints but the training distribution. You do not need another lecture on AI slop.

AHD is a toolchain that treats design as a constraint-satisfaction problem with human judgment as the arbiter. You write a brief in YAML. The compiler expands it into a structured prompt. Models generate candidates. A 28-rule linter catches systemic errors. A vision-critic scaffold runs visual comparison when you have multimodal access. You pick, or you reject and regenerate.

The framework is opinionated about process, neutral about models. Swap Claude for GPT, local for frontier, vision for no-vision. The evaluation protocol stays the same.

bash
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

What ships

  • Brief compiler (YAML to structured prompt)
  • 28-rule linter (alignment, spacing, type scale, motion, accessibility)
  • Eval harness (batch generation, scoring, reproducible runs)
  • Vision-critic scaffold (screenshot comparison pipeline, ready to wire)
  • MCP server (Model Context Protocol for editor integration)
  • Editor plugins (VS Code, Zed, NeoVim — extension manifests included)
  • Eight tokens (curated design-direction prompts, versioned)

What is gated

  • Live frontier-model calls — needs API keys
  • Live vision critique — needs multimodal key + screenshot pipeline
  • Standalone npm packages for the editor plugins — pending registry setup
  • Additional tokens — under review, not yet released
