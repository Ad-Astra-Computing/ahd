Design evals for people who can tell.

\n

\n AHD is a framework for testing generated interfaces against written taste, visual rules, and the practical constraints designers and engineers already argue about.\n

\n\n
\n
Premise
\n

\n The point is not another lecture about generic output. The point is a repeatable way to name the brief, run the work, lint the surface, and make the critique inspectable.\n

\n
\n
\n\n
\n
\n
\n run the live eval\n
\n
\n 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
\n
\n

\n The command is intentionally plain: choose the brief, name the model specs, run enough samples to see patterns instead of anecdotes.\n
