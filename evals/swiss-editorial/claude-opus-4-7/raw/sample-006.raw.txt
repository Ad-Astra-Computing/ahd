  <div class="kicker">v0.4 · monorepo · reproducible</div>
  <h1>A linter, an eval, and a taste argument — for the generation of sites that all look <em>the same</em>.</h1>
  <p class="lede">AHD is a toolchain that treats design output the way we treat code output: compiled from a brief, linted against a rubric, and scored by a harness you can re-run on your own machine.</p>
  <p>You have already seen the pattern. Centred hero, pill badge, two buttons, three feature cards, gradient wash, Corporate Memphis, the same six font-pairs. That isn't aesthetic failure. It's evaluation failure. Nothing is measuring whether the output is <em>specific</em>.</p>

  <section id="eval">
    <h2>Run the eval <span class="meta">~90s · local</span></h2>
    <div class="term" role="region" aria-label="terminal">
      <div class="bar"><span>~/ahd</span><span class="lang">bash</span></div>
<pre><span class="prompt">$</span> <span class="cmd">ahd eval-live swiss-editorial \
    --brief briefs/landing.yml \
    </span><span class="flag">--models</span><span class="val"> &lt;specs&gt;</span><span class="cmd"> \
    </span><span class="flag">--n</span><span class="val"> 10</span></pre>
    </div>
    <p class="term-note">Compiles the brief, generates n candidates across the model specs, runs the 28-rule linter, routes survivors through the vision-critic, and writes a scored report to <span class="mono">./runs/</span>. The swiss-editorial preset is the one this page was built against.</p>

  <section id="manifest">
    <h2>What ships <span class="meta">today · in the repo</span></h2>
    <dl class="manifest ships">
      <div><dt>brief compiler</dt><dd>YAML in, structured intent out. Deterministic, versioned, diff-able.</dd></div>
      <div><dt>28-rule linter</dt><dd>Static checks for hero-slop, pill-badge stacks, equal-card triads, gradient clichés, and 23 other failure modes.</dd></div>
      <div><dt>eval harness</dt><dd>n-of-m generation across model specs, scored against the rubric, reports to disk.</dd></div>
      <div><dt>vision-critic scaffold</dt><dd>The pipeline and prompts. Plug your own multimodal key to activate.</dd></div>
      <div><dt>MCP server</dt><dd>Exposes brief, lint, and eval as tools to any MCP-speaking client.</dd></div>
      <div><dt>editor plugins</dt><dd>VS Code and Zed extensions, in-tree. Build from source today.</dd></div>
      <div><dt>eight tokens</dt><dd>The opinionated starter set: ink, paper, rule, muted, accent, term-bg, term-ink, term-accent.</dd></div>
    </dl>
  </section>

  <section>
    <h2>What is gated <span class="meta">external dependency · not shipped</span></h2>
    <dl class="manifest gated">
      <div><dt>live frontier-model calls</dt><dd>The harness runs, but you supply the API keys. No keys bundled, none relayed.</dd></div>
      <div><dt>live vision critique</dt><dd>Needs a multimodal key plus a screenshot pipeline (Playwright or equivalent). Scaffold is in-tree; wire it yourself.</dd></div>
      <div><dt>standalone npm packages</dt><dd>Editor plugins will publish as <span class="mono">@ahd/vscode</span> and <span class="mono">@ahd/zed</span> once the API stabilises.</dd></div>
      <div><dt>additional tokens</dt><dd>Extended palettes, type scales, and motion tokens are drafted but not merged. Eight is the committed surface.</dd></div>
    </dl>
  </section>

  <section>
    <h2>Why a rubric, not a lecture</h2>
    <p>The thesis is simple: generative systems collapse toward the mean of their training distribution unless something external pushes back. AHD is that external thing. It is not an opinion about which fonts are tasteful. It is a machine-checkable contract between a brief and its output, and a place to argue about the contract in public.</p>
    <p>If the 28 rules are wrong, open a PR against <span class="mono">rules/</span>. If the rubric is wrong, open a PR against <span class="mono">rubric.md</span>. That is the whole pitch.</p>
