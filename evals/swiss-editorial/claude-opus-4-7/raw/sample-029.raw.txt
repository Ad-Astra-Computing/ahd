  <div class="eyebrow">A framework, not a lecture</div>
  <h1>Most generated pages look the same. <em>Evaluate</em> yours against a rubric, not a vibe.</h1>

  <p class="lede">AHD is a toolchain for treating design output the way we already treat code: with a brief, a linter, and an eval harness. You write a typed brief, the compiler turns it into prompts, the linter flags the 28 failure modes that produce the slop you're tired of seeing, and the eval runs <span class="mono">n</span> samples against a rubric you can read.</p>
  <p class="lede">It is a framework for working designers, senior engineers, and founders who already know what the problem is. It does not promise originality. It measures distance from it.</p>

  <div class="thesis">
    <p>The one-liner below is the whole contract. Clone the repo, point it at a brief, pick a set of model specs, and get ten attempts scored against the Swiss-editorial rubric with per-rule deltas.</p>
    <p>No API keys ship in the box. The scaffold runs dry against recorded fixtures out of the gate.</p>
  </div>

  <div class="term" role="group" aria-label="Terminal command">
    <div class="term-head"><span>~/ahd</span><span class="lang">bash</span></div>
<pre class="term-body"><span class="prompt">$</span> ahd eval-live swiss-editorial <span class="flag">--brief</span> <span class="val">briefs/landing.yml</span> <span class="flag">--models</span> <span class="val">&lt;specs&gt;</span> <span class="flag">--n</span> <span class="val">10</span></pre>
  </div>
  <p class="term-hint">Dry-run equivalent: drop <span class="mono">eval-live</span> for <span class="mono">eval</span>; uses recorded fixtures, no keys required.</p>

  <section aria-labelledby="ships">
    <h2 id="ships">What ships <span class="count">8 modules · today</span></h2>
    <ul class="ships">
      <li><span class="n">01</span><div><span class="item-name">Brief compiler</span><span class="item-note">Typed YAML → prompt bundle + rubric. Deterministic, diffable, reviewable in PRs.</span></div></li>
      <li><span class="n">02</span><div><span class="item-name">28-rule linter</span><span class="item-note">One rule per failure mode: gradient-on-AI, hero-pill-plus-two-CTAs, three-equal-cards, shimmer, et al.</span></div></li>
      <li><span class="n">03</span><div><span class="item-name">Eval harness</span><span class="item-note">n-sample runs, per-rule deltas, reproducible seeds, JSON + HTML report.</span></div></li>
      <li><span class="n">04</span><div><span class="item-name">Vision-critic scaffold</span><span class="item-note">Runs against recorded screenshots out of the box. Swap in a live model when you have one.</span></div></li>
      <li><span class="n">05</span><div><span class="item-name">MCP server</span><span class="item-note">Exposes briefs, lint, and eval as tools to any MCP-aware client.</span></div></li>
      <li><span class="n">06</span><div><span class="item-name">Editor plugins</span><span class="item-note">VS Code and Zed. Inline rule annotations, hover diagnostics, brief scaffolding.</span></div></li>
      <li><span class="n">07</span><div><span class="item-name">Eight tokens</span><span class="item-note">The editorial starter set: ink, paper, rule, mute, accent, term-bg, term-ink, term-accent.</span></div></li>
      <li><span class="n">08</span><div><span class="item-name">CLI + docs</span><span class="item-note">Single binary, manpages, worked examples for Swiss-editorial, brutalist, and utilitarian rubrics.</span></div></li>
    </ul>
  </section>
