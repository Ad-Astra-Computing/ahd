  <h1>
    <span class="tight">A design system for an adversarial decade</span>
    The slop is the output. The prompt was the problem.
  </h1>

  <p class="lede">You have already scrolled past forty landing pages this month with the same centred hero, the same four rounded cards, the same purple gradient on the word <em>AI</em>. AHD is the framework that assumes you noticed.</p>

  <p class="sub">AHD compiles a written brief into a rule set, lints the generated markup against it, and runs a live evaluation across frontier models so you can see — row by row, token by token — where a given model drifts from the design intent. No manifesto. A harness.</p>

  <div class="cta-row">
    <a class="cta primary" href="https://github.com/ahd/ahd">Read the code →</a>
    <a class="cta" href="https://codeberg.org/ahd/ahd">forgejo mirror</a>
    <a class="cta" href="#manifest">What ships today</a>
  </div>

  <hr class="rule">

  <h2><span class="n">01</span> The one-liner</h2>
  <p class="term-cap">Run the eval locally. Ten samples, one brief, whichever models you have keys for.</p>

  <div class="term" role="region" aria-label="bash command">
    <div class="term-head">
      <div class="dots"><i></i><i></i><i></i></div>
      <div>bash · ~/ahd</div>
    </div>
    <div class="term-body"><span class="pr">$</span> <span class="cmd">ahd eval-live swiss-editorial</span> <span class="flag">--brief</span> <span class="str">briefs/landing.yml</span> <span class="flag">--models</span> <span class="str">&lt;specs&gt;</span> <span class="flag">--n</span> <span class="str">10</span>
</div>
  </div>
  <p class="small">The harness emits a JSONL trace plus a static HTML report. The linter flags each of the 28 rule violations with a line number, not a vibe.</p>

  <hr class="rule">

  <h2 id="manifest"><span class="n">02</span> What ships</h2>
  <p class="small">Available on <code style="font-family:inherit;background:#e5e0d0;padding:0 4px">main</code> today, MIT-dev-loop, runs offline against cached fixtures.</p>

  <dl class="manifest">
    <dt>brief compiler</dt>
    <dd>Turns a YAML design brief into a typed rule graph the linter and harness both consume.</dd>
    <dt>28-rule linter</dt>
    <dd>Static checks against the compiled brief — semantic structure, type scale, spacing rhythm, contrast, cliché detection.</dd>
    <dt>eval harness</dt>
    <dd>Deterministic runner that records prompt, response, rule violations, and diffs across N samples.</dd>
    <dt>vision-critic scaffold</dt>
    <dd>Local pipeline that stages screenshots and rubric prompts; pluggable backend, runs against fixtures out of the box.</dd>
    <dt>MCP server</dt>
    <dd>Exposes the compiler, linter, and harness as tools to any MCP-aware editor or agent.</dd>
    <dt>editor plugins</dt>
    <dd>In-repo sources for VS Code and Zed. Installable from the monorepo today.</dd>
    <dt>eight tokens</dt>
    <dd>A deliberately small palette: two type scales, four spacing steps, one neutral ramp, one accent. Enough to disagree with.</dd>
  </dl>

  <hr class="rule">

  <h2><span class="n">03</span> What is gated</h2>
  <p class="small">Named honestly. These are not missing features; they are dependencies the project refuses to pretend it owns.</p>

  <dl class="manifest gated">
    <dt>frontier calls <span class="gated-tag">API keys</span></dt>
    <dd>Live evaluation against GPT-class, Claude-class, and Gemini-class models requires your own keys and quota.</dd>
    <dt>vision critique <span class="gated-tag">multimodal + pipeline</span></dt>
    <dd>Running the critic on real screenshots needs a multimodal key and a configured screenshot pipeline (Playwright or equivalent).</dd>
    <dt>npm packages <span class="gated-tag">planned</span></dt>
    <dd>Standalone, versioned npm releases of the editor plugins. Currently only installable from the monorepo.</dd>
    <dt>additional tokens <span class="gated-tag">queued</span></dt>
    <dd>Extensions beyond the eight — motion, density, per-surface overrides — sit behind validation we haven't finished.</dd>
  </dl>

  <div class="thesis">
    If you disagree with the eight tokens or the 28 rules, fork the repo and change them. That is the use case. AHD is a harness for arguments, not an opinion to adopt.
  </div>
