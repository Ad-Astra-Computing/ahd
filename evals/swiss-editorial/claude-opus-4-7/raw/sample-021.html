An eval harness for the parts of design that don't grade themselves.

You have seen the same landing page forty times this month. Centred hero, pill badge, purple-to-blue wash, three cards, a logo bar. It renders. It passes lint. It is also indistinguishable from every other page the model produced yesterday.

AHD does not write that page for you. It runs a brief against a grammar of editorial rules, scores the output with a vision critic, and returns a diff you can argue with. It is a framework, not a generator. The house style is yours.

~/ahd · zsh · 80×24 bash 
# Run ten generations against the swiss-editorial brief, evaluated live.
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

[compile]  brief.yml → 41 constraints, 8 tokens bound
[lint]     28/28 rules loaded
[critic]   vision-critic: scaffold (gated, see manifest)
[eval]     n=10 · median score 0.71 · dispersion 0.18
[write]    runs/2026-04-22T0931/ (diff, renders, trace.jsonl)
Fig. 1 — one-liner. Deterministic where it can be, honest where it can't.
Position

The output of a frontier model on an unopinionated brief is the statistical mean of the training set. On a landing page, the mean is slop. AHD's claim is narrow: if the brief is structured and the critic is adversarial, the mean moves.

No novelty. The linter rules are older than the model. The tokens are eight, because eight is enough for the editorial surface we target. Everything below is what is actually in the repo today.

Manifest two columns · eleven items

What ships ● in repo · today

  1. 01 Brief compiler YAML → typed constraint graph; validates against the rule set before any generation runs.
  2. 02 28-rule linter Editorial and typographic rules: measure, leading ratio, orphan widow, optical alignment, rag.
  3. 03 Eval harness Runs N generations, scores each, writes a reproducible trace.
  4. 04 Vision-critic scaffold Prompt templates, rubric loader, adapter interface. Stub critic returns deterministic scores for tests.
  5. 05 MCP server Exposes compile, lint, and eval to any MCP-speaking client.
  6. 06 Editor plugins In-tree sources for VS Code and Zed. Build locally; no registry yet.
  7. 07 Eight tokens ink, paper, accent, muted, rule, measure, leading, grid. Everything else is derived.

What is gated ○ external dep

  1. 08 Live frontier-model calls api key Bring your own keys. The harness never ships credentials; rate and spend are your concern.
  2. 09 Live vision critique multimodal + pipeline Needs a multimodal key and the headless screenshot pipeline. Scaffold runs without it; scores are stubbed.
  3. 10 Standalone npm packages for the editor plugins unreleased Source is in-tree. Marketplace listings are not cut until the API stops moving.
  4. 11 Additional tokens roadmap Motion, elevation, and density tokens are drafted; not bound until their rules land in the linter.

Everything above is verifiable. The repository is the spec.
