AHD — Artificial Human Design
v0.3 · 2026-04

A framework for design that still reads like it was made on purpose, not regressed toward the mean.

You've seen the pages. Centred hero, pill badge, three equal cards, a purple-to-blue smear on the word AI. They all argue for themselves in the same voice because they were all written by the same six models with the same system prompt.

AHD is the eval harness, linter, and token set that treats this as a measurable regression. It compiles a brief, lints the output against 28 rules derived from post-war Swiss editorial work, and scores live frontier model renders against a vision critic. The point is not to be anti-AI. The point is to stop grading on a curve.

01

Run the eval

~/ahdbash
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
Ten renders per model, linted against the 28 rules, then passed to the vision critic. Output is a diff, not a vibe.
02

What ships

brief compiler
YAML brief → structured constraint graph the linter and critic both read.
28-rule linter
Typographic, compositional, and semantic rules. Every rule cites its source.
eval harness
Deterministic runner for N renders per model with per-rule scoring.
vision-critic scaffold
Pluggable critic interface, local stub backend, golden fixtures.
MCP server
Exposes compiler, linter, and harness to any MCP-speaking client.
editor plugins
VS Code and Zed integrations, in-repo, built from this monorepo.
eight tokens
Type scale, grid, ink, paper, rule, accent, measure, rhythm. CC-BY-4.0.
03

What is gated

live frontier calls
Requires your own API keys. No proxy, no telemetry, no rate-limit reseller.
live vision critique
Needs a multimodal key plus a screenshot pipeline (Playwright or equivalent).
standalone npm packages
Editor plugins are currently in-tree; separate npm releases land when the plugin API stabilises.
additional tokens
Further token families (editorial-mono, grotesque-display, archival-colour) are drafted and not yet published.
