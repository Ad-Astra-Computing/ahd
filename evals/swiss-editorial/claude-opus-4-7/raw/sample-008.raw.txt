  <h1>
    A framework for design that survives contact with a language model.
    <span class="ex">Not a style. A brief compiler, a linter, and a live eval.</span>
  </h1>

  <p class="lede">
    You already know the shape of the problem. Every landing page from the last month
    is the same centred hero, the same pill badge, the same two buttons, the same
    three-card grid. The model learned the median and is serving it back.
  </p>
  <p class="lede">
    AHD treats that as a measurable defect. A brief becomes a typed spec; a draft is
    linted against twenty-eight rules; a page is graded live, against the same brief,
    across n models. Pass the eval or don't ship. That's the loop.
  </p>

  <hr class="rule">

  <h2>Run the eval</h2>
  <p class="note">One command. Renders n candidates against the Swiss-editorial brief, lints, then grades.</p>
  <div class="term" role="region" aria-label="bash terminal">
    <div class="bar">
      <span class="dots"><i></i><i></i><i></i></span>
      <span>bash — ahd</span>
      <span>~/ahd</span>
    </div>
<pre><code><span class="tok-comment"># install: cargo install ahd  (or: npm i -g @ahd/cli)</span>
<span class="tok-prompt">$</span> <span class="tok-cmd">ahd eval-live swiss-editorial</span> <span class="tok-flag">--brief</span> <span class="tok-str">briefs/landing.yml</span> <span class="tok-flag">--models</span> <span class="tok-str">&lt;specs&gt;</span> <span class="tok-flag">--n</span> <span class="tok-num">10</span>
</code></pre>
  </div>

  <p class="note" style="margin-top:14px">
    Output: a scored matrix (rule-pass, vision-critic score, brief-coverage), plus
    the rendered HTML for every candidate, checked into <code>.ahd/runs/</code>.
  </p>

  <section class="manifest">
    <h2>What ships</h2>
    <p class="note">In the repository today. No waitlist, no key required.</p>
    <dl>
      <dt>brief-compiler <span class="status s-ship">ships</span></dt>
      <dd>YAML &rarr; typed IR for constraints, tone, structure, and anti-patterns.
        <em>ahd compile briefs/landing.yml</em></dd>

      <dt>linter (28 rules) <span class="status s-ship">ships</span></dt>
      <dd>Static checks for slop signatures: centred hero stacks, triplicate cards, gradient-on-AI, shimmer, emoji bullets, canonical 4-col footers, and twenty-two more.
        <em>ahd lint ./dist</em></dd>

      <dt>eval-harness <span class="status s-ship">ships</span></dt>
      <dd>Deterministic runner: n candidates &times; m models, scored against the compiled brief.</dd>

      <dt>vision-critic <span class="status s-ship">ships</span></dt>
      <dd>Scaffold and rubric. Works today against local screenshots with a stub critic; swap in a real model below.</dd>

      <dt>mcp-server <span class="status s-ship">ships</span></dt>
      <dd>Exposes compiler, linter, and harness over MCP. Any MCP-capable client can drive the loop.</dd>

      <dt>editor plugins <span class="status s-ship">ships</span></dt>
      <dd>VS Code and Zed, in-tree. Inline lint, brief-aware completions, one-key eval.</dd>

      <dt>tokens (8) <span class="status s-ship">ships</span></dt>
      <dd>swiss-editorial, brutalist-grid, archive-quiet, monospace-manual, terminal-paper, broadsheet, civic-signage, almanac.</dd>
    </dl>
  </section>
