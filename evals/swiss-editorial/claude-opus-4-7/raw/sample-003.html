AHD / Artificial Human Design
Manifest Code

The slop has a shape. We measure it.

AHD is a framework for evaluating generated interface design against a compiled brief — not vibes, not a leaderboard, not a thread. A 28-rule linter, a Swiss-editorial reference brief, and a harness that runs models head-to-head against it.

You already know the problem. This is the working draft of a method.

Run the eval

bashahd · v0.4.2
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
› emits: lint report, rendered diffs, vision-critic notes (gated), JSONL trace

What ships — today, in the repo

brief compiler
YAML brief → structured constraints the linter and harness can both read.
28-rule linter
Deterministic checks against the compiled brief. No model calls.
eval harness
Runs N samples per model spec, captures artifacts, scores them.
vision-critic scaffold
Prompt templates, rubric, screenshot handoff — wiring only.
MCP server
Exposes the brief, linter, and harness as tools to an MCP client.
editor plugins
In-tree plugins for Zed and Neovim, loaded from source.
eight tokens
The canonical reference set: scale, measure, rule, ink, paper, accent, rhythm, weight.

What is gated — requires something you bring

live frontier-model calls
The harness will not run against hosted models without your API keys in env.
live vision critique
Needs a multimodal key plus a working screenshot pipeline (Playwright or equivalent).
npm packages
Standalone published builds of the editor plugins are not cut yet; install from source.
additional tokens
Expansions beyond the eight — grid, motion, density — are scheduled, not shipped.
