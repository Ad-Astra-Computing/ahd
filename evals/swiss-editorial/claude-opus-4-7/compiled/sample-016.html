01 / A framework not a lecture

Most generated sites
look the same.
This one doesn't.

AHD is a design system for people who already know why the last thirty landing pages looked identical. A brief compiler. A linter that reads for taste. An eval harness that runs the same brief across frontier models and grades the output against the token.

You do not need to be sold on the slop thesis. You are reading this because you already have an opinion. Below: what works today, what is gated on keys you control, and the exact command that runs the eval.
AHD

Taste.

Measured as rule adherence against a declarative token. Twenty-eight rules. One baseline. Eight tokens. No vibes, no juries, no committee decks.

03 / Manifest

What ships today. What is gated on keys you already own.

What ships

  1. Brief compilerYAML briefs compile to a deterministic prompt and a rule set.
  2. 28-rule linterStatic checks for typography, grid, palette, rhythm and forbidden patterns.
  3. Eval harnessRuns a brief across N models, scores against the token, writes a report.
  4. Vision-critic scaffoldLocal pipeline for rendered-screenshot critique. Bring your own model.
  5. MCP serverExposes briefs, tokens and the linter to any MCP-aware client.
  6. Editor pluginsVS Code and Zed integrations for compile, lint and preview.
  7. Eight tokensSwiss Editorial, Brutalist Web, Editorial Serif, Utility Mono, and four more.

What is gated needs keys

  1. Live frontier-model callsRequires your own API keys. No hosted inference. No relay.
  2. Live vision critiqueNeeds a multimodal key plus a screenshot pipeline you point at a URL.
  3. Standalone npm packagesThe editor plugins exist in-repo; separate published packages are not cut yet.
  4. Additional tokensBeyond the eight shipped; contributions welcome once the token schema freezes.
