  <h1>A framework for design that refuses to look <em>autogenerated</em>.</h1>

  <p class="lede">
    You have seen the sites. Centred hero, pill badge, two buttons, three equal
    cards, a shimmer on the word <span class="q">AI</span>, a footer with four columns in the
    canonical order. You did not need another deck to tell you what was wrong.
  </p>
  <p class="lede">
    AHD — Artificial Human Design — treats slop as a measurable failure mode.
    It compiles a brief into constraints, lints output against 28 rules a
    working art director would actually notice, and runs live evals against
    frontier models so the regression is visible before it ships.
  </p>

  <aside class="slop-aside">
    The problem is not that models generate pages. The problem is that models
    generate <em>the same page</em>. AHD is an opinion, enforced in code,
    about what separates a layout from a pattern you have already seen this week.
  </aside>

  <div class="meta">run the eval</div>
  <pre class="term"><div class="term-bar"><span>~/ahd</span><span class="lang">bash</span></div><div class="term-body"><span class="p">$ </span><span class="cmd">ahd eval-live swiss-editorial</span> <span class="flag">--brief</span> <span class="arg">briefs/landing.yml</span> <span class="flag">--models</span> <span class="arg">&lt;specs&gt;</span> <span class="flag">--n</span> <span class="arg">10</span></div></pre>
  <p class="term-note">
    10 samples per model, scored by the linter and (with a key) the vision critic.
    Output is a diff against the brief, not a vibe.
  </p>

  <section class="block">
    <h2>What ships</h2>
    <p class="sub">In the repo today. Clone it, run it, disagree with it.</p>
    <dl class="manifest shipped">
      <dt>Brief compiler</dt>
      <dd>YAML → constraint graph. Grid, rhythm, voice, refusals.</dd>

      <dt>28-rule linter</dt>
      <dd>Static checks for the failure modes you are tired of. Centred stacks, gradient text, equal-card layouts, corporate illustration, and so on.</dd>

      <dt>Eval harness</dt>
      <dd>Deterministic scoring over N samples. Produces a per-rule regression table.</dd>

      <dt>Vision-critic scaffold</dt>
      <dd>Screenshot → rubric → score. Rubric is shipped; the multimodal call is not.</dd>

      <dt>MCP server</dt>
      <dd>Exposes the compiler, linter and harness to any MCP-capable client.</dd>

      <dt>Editor plugins</dt>
      <dd>Source-tree integrations for VS Code, Zed, and Neovim. In-repo today.</dd>

      <dt>Eight tokens</dt>
      <dd>A starter type / colour / spacing set that passes the linter. Swiss-editorial, not beige.</dd>
    </dl>
  </section>

  <section class="block">
    <h2>What is gated</h2>
    <p class="sub">Honest about the edges. These require something you bring.</p>
    <dl class="manifest gated">
      <dt>Live frontier-model calls</dt>
      <dd>The harness will run; the models will not answer without credentials.
        <span class="req">needs: API keys (OpenAI / Anthropic / etc.)</span>
      </dd>

      <dt>Live vision critique</dt>
      <dd>Scaffold is in; the multimodal round-trip is not wired by default.
        <span class="req">needs: multimodal key + screenshot pipeline (playwright)</span>
      </dd>

      <dt>Standalone npm packages</dt>
      <dd>The editor plugins currently live in the monorepo. Independent publishing is planned, not done.
        <span class="req">status: unpublished</span>
      </dd>

      <dt>Additional tokens</dt>
      <dd>Beyond the eight shipped. Editorial-serif, brutalist-grid, and mono-zine sets are drafted but not released.
        <span class="req">status: drafted, not cut</span>
      </dd>
    </dl>
  </section>
