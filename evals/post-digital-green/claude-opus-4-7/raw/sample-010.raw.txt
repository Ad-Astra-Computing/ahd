  <h1>A framework against <em>design slop</em>, not another opinion about it.</h1>
  <p class="dek">You've seen the month. Twenty landing pages that are the same landing page: the same hero, the same three cards, the same pill, the same gradient on the same word. AHD is the toolchain that makes that failure visible in an eval the way a failing test is visible in CI. It does not argue with taste. It measures it.</p>

  <p>AHD compiles a <em>brief</em> — a yaml contract of audience, surface, must-include, must-avoid — into constraints a model can be graded against. The linter runs 28 rules for the things you are tired of seeing. The eval harness runs N generations against a frontier model, scores each, and prints a table. You can read the output in a terminal. You can read the rules in a text editor. That is the entire premise.</p>

  <section>
    <h2>Run the eval <span class="ct">~/ahd</span></h2>
    <div class="term" role="region" aria-label="terminal">
      <div class="bar"><span>bash</span><span>ahd · eval-live</span></div>
<pre><span class="p">$</span> <span class="cmd">ahd eval-live swiss-editorial</span> <span class="arg">--brief</span> <span class="val">briefs/landing.yml</span> <span class="arg">--models</span> <span class="val">&lt;specs&gt;</span> <span class="arg">--n</span> <span class="val">10</span></pre>
    </div>
    <p class="caption">Ten generations, one brief, one grader. Exit non-zero on any rule in the avoid-list.</p>

  <div class="note">AHD is a framework, not a generator. It will tell you your homepage is slop. It will not rewrite it for you.</div>

  <section>
    <h2>What ships <span class="ct">today · in this repo</span></h2>
    <ul class="manifest">
      <li><span class="n">01</span><span class="t"><b>brief compiler</b> <span>— yaml → constraint graph, deterministic, no network.</span></span></li>
      <li><span class="n">02</span><span class="t"><b>28-rule linter</b> <span>— gradient-word, pill-plus-two-CTAs, Corporate Memphis, trusted-by bar, etc.</span></span></li>
      <li><span class="n">03</span><span class="t"><b>eval harness</b> <span>— N runs, per-rule scoring, tabular + JSON output.</span></span></li>
      <li><span class="n">04</span><span class="t"><b>vision-critic scaffold</b> <span>— prompts, rubric, screenshot diffing, runs on fixtures.</span></span></li>
      <li><span class="n">05</span><span class="t"><b>MCP server</b> <span>— exposes compiler, linter, harness to any MCP-aware client.</span></span></li>
      <li><span class="n">06</span><span class="t"><b>editor plugins</b> <span>— VS Code &amp; Zed, in-tree, built from this repo.</span></span></li>
      <li><span class="n">07</span><span class="t"><b>eight tokens</b> <span>— swiss-editorial starter set: ink, paper, rule, mute, accent, measure, stack, grid.</span></span></li>
    </ul>
  </section>

  <section>
    <h2>What is gated <span class="ct">needs external resources</span></h2>
    <ul class="manifest gated">
      <li><span class="n">08</span><span class="t"><b>live frontier-model calls</b> <span>— needs your API keys; harness runs on fixtures without them.</span></span></li>
      <li><span class="n">09</span><span class="t"><b>live vision critique</b> <span>— needs a multimodal key and a screenshot pipeline (headless chromium).</span></span></li>
      <li><span class="n">10</span><span class="t"><b>standalone npm packages for the editor plugins</b> <span>— in-tree today, marketplace builds pending.</span></span></li>
      <li><span class="n">11</span><span class="t"><b>additional tokens</b> <span>— editorial-mono, brutalist-doc, long-form serif; drafted, not released.</span></span></li>
