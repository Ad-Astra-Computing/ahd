    <section aria-label="Thesis">
      <h1>A framework for evaluating <em>generated</em> interfaces against editorial taste.</h1>
      <p class="lede">
        You already know the failure mode: default card, default gradient, default three-up grid,
        same section shapes repeated across unrelated products. AHD treats that pattern as an eval
        problem, not a style opinion. The linter, the vision-critic, and the harness exist so a
        model's output can fail a brief the way a junior's work fails a crit — specifically, in
        writing, against rules you can read.
      </p>
      <p class="sub">
        The project is a set of compilers and checks, not a design system. It does not produce
        sites. It scores them.
      </p>

      <div class="cta-row">
        <a class="primary" href="https://github.com/ahd/ahd">→ Read the code on GitHub</a>
        <span class="hint">mirror: <a href="https://forgejo.ahd.dev/ahd/ahd">forgejo.ahd.dev/ahd/ahd</a></span>
      </div>
    </section>

    <section aria-label="Run the eval">
      <h2>Run the eval</h2>
      <p class="sub" style="margin-bottom:14px;">
        Feeds a brief YAML to <em>n</em> models, renders their output, runs the 28-rule linter and
        the vision-critic, and prints a per-rule scorecard. Live frontier calls require keys; see
        the manifest below.
      </p>
      <div class="term" role="region" aria-label="terminal">
        <div class="chrome">
          <span>bash · zsh · fish</span>
          <span>eval-live · swiss-editorial</span>
        </div>
<pre><span class="cmt"># score 10 completions per model against the swiss-editorial brief</span>
<span class="prompt">$</span> <span class="cmd">ahd eval-live swiss-editorial \
    --brief briefs/landing.yml \
    --models &lt;specs&gt; \
    --n 10</span></pre>
      </div>
    </section>

    <section class="thesis" aria-label="Posture">
      <div>
        <h3>Posture</h3>
        <p>
          The output of a generative model is a draft. A draft deserves a crit. A crit deserves
          rules written down. AHD writes them down.
        </p>
      </div>
      <div>
        <h3>Non-goals</h3>
        <p>
          Not a component library. Not a hosted product. Not a design agency in a box. Not a
          replacement for taste — a place to put it.
        </p>
      </div>
