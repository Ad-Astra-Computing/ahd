    <h1>
      Artificial Human Design
      <span class="sub">A framework for evaluating — and resisting — generated design slop.</span>
    </h1>

    <p class="lede">
      You already know the problem. Another month, another wave of landing pages that are
      technically correct and aesthetically <em>indistinguishable</em>. AHD is a small,
      opinionated toolkit that treats "did a model produce slop?" as a question with an
      answer, not a vibe.
    </p>

    <div class="thesis">
      <p>AHD compiles a written brief into constraints, lints generated markup against 28 concrete rules, and runs a live eval across frontier models so you can see — side by side — which outputs hold a position and which ones average themselves into nothing.</p>
      <p>It is a framework, not a lecture. Run it on your own briefs. Disagree with the rules. Fork the linter.</p>
    </div>

    <div class="cta-row">
      <a class="primary" href="https://github.com/ahd/ahd">github.com/ahd/ahd</a>
      <a href="https://code.forgejo.org/ahd/ahd">forgejo mirror</a>
      <span class="small">npm i -g @ahd/cli</span>
    </div>

    <section id="run">
      <h2><span>§ 01 · Run the eval</span><span class="count">~9s cold, ~2s warm</span></h2>
      <p>One command. Ten generations per model. Linted, scored, and diffed against the brief.</p>
      <div class="term" role="group" aria-label="bash command">
        <div class="bar">
          <div class="dots"><i></i><i></i><i></i></div>
          <div>bash — ahd eval-live</div>
          <div>~/work/ahd</div>
        </div>
<pre><span class="comment"># language: bash</span>
<span class="prompt">$</span> <span class="cmd">ahd eval-live swiss-editorial</span> <span class="flag">--brief</span> <span class="str">briefs/landing.yml</span> <span class="flag">--models</span> <span class="str">&lt;specs&gt;</span> <span class="flag">--n</span> <span class="num">10</span></pre>
        <div class="caption">writes ./runs/&lt;ts&gt;/ — raw html, lint report, vision-critic json, per-rule deltas</div>
      </div>
      <p class="small">&lt;specs&gt; is a comma-separated list of model IDs registered in <code>ahd.models.toml</code>. Live calls require keys — see below.</p>
    </section>

    <section id="manifest">
      <h2><span>§ 02 · The manifest</span><span class="count">honest about the seams</span></h2>

      <div class="ships manifest-grid" style="margin-bottom:22px">
        <div class="manifest-col ships" style="grid-column:1 / -1">
          <header>
            <span>What ships</span>
            <span class="status">✓ in this repo, today</span>
          </header>
          <ol>
            <li>
              <span class="name">Brief compiler</span>
              <span class="note">YAML + prose in, structured constraints out. Used by every downstream stage.</span>
            </li>
            <li>
              <span class="name">28-rule linter</span>
              <span class="note">Static rules for the patterns this page's "must avoid" list is drawn from. Runs on generated HTML/CSS.</span>
            </li>
            <li>
              <span class="name">Eval harness</span>
              <span class="note">Deterministic runner, fixture cache, per-rule scoring, side-by-side diff output.</span>
            </li>
            <li>
              <span class="name">Vision-critic scaffold</span>
              <span class="note">Screenshot → rubric → structured critique. Scaffold and schema only; see "gated" for live calls.</span>
            </li>
            <li>
              <span class="name">MCP server</span>
              <span class="note">Exposes the compiler, linter, and harness as tools to any MCP-speaking editor or agent.</span>
            </li>
            <li>
              <span class="name">Editor plugins</span>
              <span class="note">VS Code and Zed sources in <code>/editors</code>. Load unpacked; standalone packages are still gated.</span>
            </li>
            <li>
              <span class="name">Eight tokens</span>
              <span class="note">Type scale, rule weights, paper/ink pair, an accent, two mono families. Enough for the default system. No more.</span>
            </li>
          </ol>
        </div>
      </div>

      <div class="gated manifest-grid">
        <div class="manifest-col gated" style="grid-column:1 / -1">
          <header>
            <span>What is gated</span>
            <span class="status">◌ requires external resources</span>
          </header>
          <ol>
            <li>
              <span class="name">Live frontier-model calls</span>
              <span class="note">The harness will happily replay fixtures; calling real models is behind your own keys.</span>
              <span class="need">needs: API keys (per-provider, BYOK)</span>
            </li>
            <li>
              <span class="name">Live vision critique</span>
              <span class="note">The scaffold accepts screenshots and returns structured critique only when wired to a multimodal endpoint and a capture pipeline.</span>
              <span class="need">needs: multimodal key + screenshot pipeline (Playwright or equivalent)</span>
            </li>
            <li>
              <span class="name">Standalone npm packages for the editor plugins</span>
              <span class="note">Sources are in-tree and load unpacked. Signed, versioned marketplace builds are not published yet.</span>
              <span class="need">needs: publisher accounts, signing, release cadence</span>
            </li>
            <li>
              <span class="name">Additional tokens</span>
              <span class="note">Anything beyond the default eight. Alternate type pairings, dark paper, narrower grids — all welcome as forks, none in core.</span>
              <span class="need">needs: a PR with rationale, or your own token pack repo</span>
            </li>
          </ol>
        </div>
      </div>
