  <h1>A framework against <em>design slop</em>, with an eval you can run before you merge.</h1>

  <p class="lede">
    You already know what the web looks like after twelve months of prompt-to-page.
    AHD is a small, opinionated toolchain that treats generated UI as something to
    <b>lint, critique, and evaluate</b> — not something to applaud. One brief. One
    linter. One command. Real numbers.
  </p>

  <div class="cta-row">
    <a class="cta" href="https://github.com/ahd/ahd" rel="noopener">
      <span class="arrow">→</span>read the code on GitHub
    </a>
    <small>mirror: forgejo.ahd.dev/ahd/ahd · MIT-adjacent, see footer</small>
  </div>

  <section id="thesis" class="thesis">
    <h2><span class="num">§1</span>Why this exists</h2>
    <p>
      Most AI-generated pages fail the same ways: centred hero, pill badge, two
      CTAs, three equal cards, a purple-to-blue gradient on the word <i>AI</i>, a
      Trusted-by row of logos nobody recognises. The models aren't broken. The
      briefs are thin and the evaluation is vibes.
    </p>
    <p>
      AHD compiles a structured brief, lints the output against 28 concrete rules
      derived from Swiss editorial practice, and runs a live eval harness over N
      models per prompt. You get a scorecard, not a screenshot.
    </p>
    <div class="rule-row">
      <span>rule-03 no-pill-badge</span>
      <span>rule-11 no-gradient-on-AI</span>
      <span>rule-17 no-three-equal-cards</span>
      <span>+25 more</span>
    </div>
  </section>

  <section id="eval">
    <h2><span class="num">§2</span>The one-liner</h2>
    <p>Scores ten generations of the <code>swiss-editorial</code> template against the brief at <code>briefs/landing.yml</code>, across whichever model specs you pass:</p>

    <div class="term" role="figure" aria-label="terminal code block, language bash">
      <div class="bar">
        <span class="dot r"></span><span class="dot y"></span><span class="dot g"></span>
        <span>zsh — ahd</span>
        <span class="tag">bash</span>
      </div>
<pre><span class="comment"># run the live eval, 10 generations per model</span>
<span class="prompt">$</span> <span class="cmd">ahd</span> <span class="arg">eval-live</span> <span class="arg">swiss-editorial</span> <span class="flag">--brief</span> <span class="val">briefs/landing.yml</span> <span class="flag">--models</span> <span class="val">&lt;specs&gt;</span> <span class="flag">--n</span> <span class="val">10</span>
<span class="comment">» compiling brief ......................... ok (42 constraints)</span>
<span class="comment">» dispatching to 3 model specs × n=10 ...... 30 candidates</span>
<span class="comment">» linter: 28 rules × 30 candidates ......... 840 checks</span>
<span class="comment">» vision-critic: requires multimodal key ... SKIPPED</span>
<span class="comment">» scorecard → .ahd/runs/2026-04-24T0931Z/</span>
</pre>
    </div>
    <p class="cmd-note">Replace <code>&lt;specs&gt;</code> with e.g. <code>anthropic:claude-x,openai:gpt-y</code>. API keys are yours; AHD never ships with them.</p>
  </section>

  <section id="ships">
    <h2><span class="num">§3</span>What ships</h2>
    <div class="manifest" style="border-bottom:none;padding-bottom:0">
      <div style="grid-column:1 / -1">
        <h3>What ships <span class="pill">TODAY</span></h3>
        <ol>
          <li><span><b>brief compiler</b> — YAML → constrained prompt graph with typed slots.<span class="note">deterministic, reproducible, diffable between runs.</span></span></li>
          <li><span><b>28-rule linter</b> — catches pill badges, gradient-on-AI, equal-three-card layouts, and 25 more.<span class="note">plain JS, no model call required.</span></span></li>
          <li><span><b>eval harness</b> — runs N generations per model spec and produces a scorecard.<span class="note">outputs JSON, Markdown, and a static HTML report.</span></span></li>
          <li><span><b>vision-critic scaffold</b> — prompts, rubric, and pipeline wiring. Bring your own multimodal key.</span></li>
          <li><span><b>MCP server</b> — exposes brief, linter, and eval to any MCP-capable editor or agent.</span></li>
          <li><span><b>editor plugins</b> — VS Code and Zed integrations, installed from this repo.</span></li>
          <li><span><b>eight tokens</b> — the starter token set: ink, paper, rule, accent, muted, term-bg, term-fg, term-accent.<span class="note">CC-BY-4.0, drop-in as CSS custom properties.</span></span></li>
        </ol>
      </div>
    </div>
  </section>

  <section id="gated">
    <div class="manifest" style="border-top:none;padding-top:0">
      <div style="grid-column:1 / -1">
        <h3>What is gated <span class="pill warn">NEEDS EXTERNAL</span></h3>
        <ol>
          <li><span><b>live frontier-model calls</b> — the harness will dispatch to hosted models only when you supply your own API keys.<span class="note">env: AHD_ANTHROPIC_KEY, AHD_OPENAI_KEY, etc.</span></span></li>
          <li><span><b>live vision critique</b> — requires a multimodal key <i>and</i> a working screenshot pipeline (Playwright or a render service).</span></li>
          <li><span><b>standalone npm packages for the editor plugins</b> — today they install from source; individually published packages are tracked on the roadmap.</span></li>
          <li><span><b>additional tokens</b> — the grid, motion, and density packs ship after the token RFC lands.</span></li>
        </ol>
      </div>
    </div>
  </section>

  <section>
    <h2><span class="num">§4</span>If you want to kick the tyres</h2>
    <p>
      Clone the repo, run the one-liner above against a brief of your own, and
      read the scorecard. If you disagree with a rule, open a PR against
      <code>rules/</code>. The linter is the argument; the eval is the evidence.
    </p>
