    <div class="meta">v0.4 · 24 apr 2026</div>
    <h1>A framework for design that <em>survives</em> the model.</h1>
    <p class="lede">
      You already know the shape of the problem. Every new landing page looks
      like the last one: the same centred stack, the same vague noun-verb
      headline, the same four feature cards. <b>AHD</b> is a small, opinionated
      toolkit that treats the slop as a measurable defect and fails the build
      when a page drifts toward it.
    </p>
    <p>
      It works in three parts. A <b>brief compiler</b> turns a YAML
      intent document into a typed constraint set. A <b>28-rule linter</b>
      checks generated markup and CSS against structural, typographic, and
      compositional rules — the kind of rules a senior designer would write
      on the back of an envelope. An <b>eval harness</b> runs a brief across
      <i>n</i> models, diffs the output against the constraints, and prints a
      pass/fail grid you can read in fifteen seconds.
    </p>
    <p>
      To try it against the reference brief — a Swiss-editorial landing page
      like this one — run:
    </p>
  </section>

  <div class="term" role="region" aria-label="shell command">
    <div class="term-head">
      <span>shell</span>
      <span class="lang">bash</span>
    </div>
    <div class="term-body"><span class="p">$</span> <span class="c">ahd</span> <span class="f">eval-live</span> <span class="v">swiss-editorial</span> <span class="n">--brief</span> briefs/landing.yml <span class="n">--models</span> &lt;specs&gt; <span class="n">--n</span> 10</div>
  </div>
  <p class="term-note">// output: a 10×K grid of rule violations, a per-model score, and a diff against the constraint set. fails noisily.</p>

  <section class="manifest" id="ships">
    <h2><span class="hash">§1</span>What ships</h2>
    <div class="sub">in the repo today · cloneable · runnable offline</div>
    <ul class="mlist">
      <li class="ok"><span class="tag">ships</span><span class="body"><b>Brief compiler.</b> YAML → typed constraint set. Deterministic, reversible, diff-friendly.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>28-rule linter.</b> Structural, typographic, and compositional checks. Exits non-zero on drift.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>Eval harness.</b> Runs a brief across <i>n</i> models, scores against the constraint set, produces a grid.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>Vision-critic scaffold.</b> The harness, prompts, and rubric. Bring your own multimodal model.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>MCP server.</b> Exposes the compiler, linter, and harness to any MCP-aware editor or agent.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>Editor plugins.</b> Source for the VS Code and Zed plugins, in-tree. Build locally.</span></li>
      <li class="ok"><span class="tag">ships</span><span class="body"><b>Eight tokens.</b> A deliberately small Swiss-editorial token set: two type scales, three colour roles, three spacing steps.</span></li>
    </ul>
  </section>

  <section class="manifest" id="gated">
    <h2><span class="hash">§2</span>What is gated</h2>
    <div class="sub">requires external resources · not bundled · documented honestly</div>
    <ul class="mlist">
      <li class="gated"><span class="tag">gated</span><span class="body"><b>Live frontier-model calls.</b> <span class="why">needs API keys you provide. the harness will run; the calls will not.</span></span></li>
      <li class="gated"><span class="tag">gated</span><span class="body"><b>Live vision critique.</b> <span class="why">needs a multimodal key and a working screenshot pipeline (Playwright or equivalent).</span></span></li>
      <li class="gated"><span class="tag">gated</span><span class="body"><b>Standalone npm packages for the editor plugins.</b> <span class="why">source is in-tree today; published packages are gated on a stable plugin API.</span></span></li>
      <li class="gated"><span class="tag">gated</span><span class="body"><b>Additional tokens.</b> <span class="why">further token sets (long-form, dashboard, documentation) arrive as the rule set stabilises, not before.</span></span></li>
    </ul>
  </section>
