A framework for rejecting generated slop before it reaches the canvas.

AHD compiles a brief into a set of hard constraints, lints the output against twenty-eight rules about hierarchy, rhythm and restraint, and re-runs that eval across every model you care to wire up. The verdict is a diff, not a vibe check.

You have already seen the symptoms: the pill badge, the two button hero, the feature card triptych, the gradient on the word it loves best. AHD treats those as failure modes with names, not aesthetic preferences. The linter catches them. The vision-critic scaffold argues about the ones that slip through.

What ships

today, from this repository, with no keys required.

  • 01Brief compiler. YAML in, constraint graph out. The source of truth every other stage reads from.stable
  • 0228-rule linter. Named failure modes, each with a citation and a reproduction from a real generated page.stable
  • 03Eval harness. Deterministic runner. Parallel per-model seeds, reproducible reports, diff-friendly output.stable
  • 04Vision-critic scaffold. Runs locally against a mocked VLM so you can develop critics without burning tokens.stable
  • 05MCP server. Exposes brief, linter and harness to any agent that speaks Model Context Protocol.stable
  • 06Editor plugins. VS Code, Zed and Neovim. Inline lint, brief-aware completions, preview of the failure trace.in-tree
  • 07Eight tokens. Typographic scale, measure, rhythm unit, grid step, ink, paper, rule, accent. Nothing else.v1

  • DAdditional tokens. Beyond the core eight. Held back until there is evidence they are load-bearing, not decorative.deferred

A note on scope

AHD does not generate your page. It tells you, with receipts, when a generated page is lying to you. The rest is still design work done by a person at a keyboard who has opinions.

If you disagree with a rule, the rule has a file. Open an issue with the counter-example. That is the entire governance model.
