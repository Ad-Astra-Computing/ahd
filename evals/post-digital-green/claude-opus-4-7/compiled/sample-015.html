ahd / artificial human design v0.1.0 · 2026-04-24

a framework for not shipping slop.

ahd is a design system compiler, linter, and eval harness for teams whose work is getting written by models. the thesis: if you can specify taste, you can test for it. if you can test for it, you can reject the mean.

you already know why the last forty landing pages looked the same. this page is the antidote, written by the tool it documents.

pipeline

  brief.yml ──▶ [compiler] ──▶ spec ──▶ [generator] ──▶ artefact
                                 │                          │
                                 ▼                          ▼
                           [28-rule linter] ◀──── [vision-critic]
                                 │                          │
                                 └────────▶ eval harness ◀──┘
                                                 │
                                                 ▼
                                             score + diff

every arrow is a unix process. every box writes plain text. the generator is replaceable; the rest is not.

run the eval

$ bash$ ahd eval-live swiss-editorial \
    --brief briefs/landing.yml \
    --models <specs> \
    --n 10 

renders n candidates per model, lints them, scores them against the brief, and writes a diff report. the one-liner is the api.

[ what ships ]

  • 01brief compiler — yaml in, typed spec out
  • 0228-rule linter — the taste assertions
  • 03eval harness — n candidates, diffed, scored
  • 04vision-critic scaffold — pluggable critic interface
  • 05mcp server — exposes ahd to any agent runtime
  • 06editor plugins — vs code, neovim, zed (in-tree)
  • 07eight tokens — swiss-editorial, post-digital-green, and six more

[ what is gated ]

  • g1live frontier-model calls — requires api keys you supply
  • g2live vision critique — requires multimodal key + screenshot pipeline
  • g3standalone npm packages for the editor plugins — not yet published
  • g4additional tokens — nine through sixteen, on the queue
