ahd / artificial human design

the problem is not that models can draw. it is that most outputs do not survive contact with taste, constraints, or review.

ahd turns that suspicion into a working method: compile the brief, lint the output, run a repeatable eval, and keep the visual language accountable to explicit rules. this is for people who already know what slop looks like and want a framework that catches it before it ships.

read-the-code 

brief.yml
   |
   v
[compiler] -> [28-rule linter] -> [eval harness] -> [critic]
   |                                                |
   '--------------------------> report <------------'

run the eval

ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

the point is not another style preset. the point is a system that can explain why an output passes, fails, or looks suspiciously like the last ten sites you saw.

what ships

  • brief compiler
  • 28-rule linter
  • eval harness
  • vision-critic scaffold
  • mcp server
  • editor plugins
  • eight tokens

what is gated

  • live frontier-model calls (needs api keys)
  • live vision critique (needs multimodal key + screenshot pipeline)
  • standalone npm packages for the editor plugins
  • additional tokens
