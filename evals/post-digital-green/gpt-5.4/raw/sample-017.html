AHD

Design systems for evaluating taste under machine pressure.

Most AI-generated sites fail in recognizable ways: borrowed posture, inflated certainty, default layout grammar, zero editorial judgment. AHD treats that as an evaluation problem first.

It gives designers, engineers, and founders a way to compile a brief, lint outputs against explicit rules, run comparative evals, and inspect what is real today versus what still depends on external keys and pipelines.

Run It
eval-live
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

AHD ships as a usable stack, not a mood board. The split below is literal: what exists now, and what remains conditional on outside services.

What ships

  • brief compiler
  • 28-rule linter
  • eval harness
  • vision-critic scaffold
  • MCP server
  • editor plugins
  • eight tokens

What is gated

  • live frontier-model calls (needs API keys)
  • live vision critique (needs multimodal key + screenshot pipeline)
  • standalone npm packages for the editor plugins
  • additional tokens
