          <h1 id="hero-title" class="headline">Design evaluation with standards, not vibes.</h1>

          <div class="subgrid">
            <p class="lede">
              AHD treats generative design as an editorial problem. The brief is compiled, the output is linted against explicit rules, and the result is evaluated in a repeatable loop. That gives designers, engineers, and founders a way to inspect the work instead of arguing about taste in the abstract.
            </p>
            <div class="aside">
              One screen. One command. A manifest of what exists now and what still depends on outside infrastructure.
            </div>

      <section class="manifest-wrap" aria-label="Manifest sections">
        <section id="what-ships" class="panel manifest" aria-labelledby="ships-title">
          <span class="label">Manifest</span>
          <h2 id="ships-title">What ships</h2>
          <ul>
            <li><strong>brief compiler</strong> that turns intent into structured evaluation input</li>
            <li><strong>28-rule linter</strong> that flags the common visual and structural failure modes</li>
            <li><strong>eval harness</strong> for running comparative passes across model specs</li>
            <li><strong>vision-critic scaffold</strong> for image-based review hooks and score plumbing</li>
            <li><strong>MCP server</strong> for tool-aware integration in editor and agent workflows</li>
            <li><strong>editor plugins</strong> for working inside the places teams already edit</li>
            <li><strong>eight tokens</strong> that encode the current design vocabulary</li>
          </ul>
        </section>

        <section class="panel manifest" aria-labelledby="gated-title">
          <span class="label">Manifest</span>
          <h2 id="gated-title">What is gated</h2>
          <ul>
            <li><strong>live frontier-model calls</strong> requiring API keys</li>
            <li><strong>live vision critique</strong> requiring a multimodal key and screenshot pipeline</li>
            <li><strong>standalone npm packages for the editor plugins</strong> not yet split from the current distribution path</li>
            <li><strong>additional tokens</strong> still pending curation and release</li>
          </ul>
        </section>
      </section>

      <section class="closing" aria-label="Closing summary">
        <div class="panel">
          <span class="label">Position</span>
          <p>
            The point is not to produce another style of generated sameness with better copy around it. The point is to make quality legible: what the brief asked for, which rules were violated, which outputs held up, and which parts still depend on external model access.
          </p>
        </div>
        <div class="panel">
          <span class="label">Read Path</span>
