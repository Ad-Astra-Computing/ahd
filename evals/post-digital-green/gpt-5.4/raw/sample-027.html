Design evaluation for people who are already tired of the pattern

A framework for calling design slop what it is.

AHD does not argue that generic output exists. You can see it. The point is to make that judgment legible, repeatable, and hard to hand-wave away.

It turns a design brief into explicit constraints, runs multi-sample evaluations, and exposes where a system collapses into defaults, imitation, or empty polish.

One screen, one standard: if a model cannot hold a brief under pressure, the problem is not taste. It is process, instrumentation, and missing constraints.
eval.live sample command 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

AHD is for designers, engineers, and founders who want a framework they can inspect, run, and argue with directly.

What it is for

Use it when the output looks polished enough to pass a casual review but brittle enough to fail the brief. AHD makes that failure measurable.

How it reads

Brief in. Rules compiled. Variants generated. Results linted. Critique scaffolded. The artifact is not a moodboard; it is an evaluation record.

Bias of the project

Preference for strong composition, explicit typography, and design systems that survive contact with real constraints instead of dissolving into template habits.

What ships

  • brief compilerTurns a written brief into enforceable evaluation structure.
  • 28-rule linterChecks for recurring failure modes instead of vague impressions.
  • eval harnessRuns repeated samples so one lucky output does not hide the median.
  • vision-critic scaffoldProvides the critique layer and interface for visual review workflows.
  • MCP serverExposes AHD capabilities to connected tooling and editor workflows.
  • editor pluginsIn-editor surfaces for running checks and reviewing outputs.
  • eight tokensCurrent design token set included in the project.

What is gated

  • live frontier-model callsNeeds API keys.
  • live vision critiqueNeeds multimodal key + screenshot pipeline.
  • standalone npm packages for the editor pluginsCurrent plugin work ships inside the repo rather than as separate published packages.
  • additional tokensMore token sets depend on external release work.
