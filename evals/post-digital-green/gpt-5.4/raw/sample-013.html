Framework, not sermon

Generated work needs a standard that can survive inspection.

AHD is for people who have already seen the pattern: polished noise, flattened taste, defaulted layouts, and no durable way to say why a result failed. The point is not more prompts. The point is a brief compiler, a rule set, and an eval loop that makes visual judgment legible enough to work with.

eval-live terminal 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

What AHD does differently

It treats design output as something you can test against declared intent instead of something you decorate after generation.

It keeps the line between what works today in-repo and what still depends on external keys, multimodal access, or packaging effort visible.

It gives designers, engineers, and founders a common object to argue over: the brief, the rules, the failures, and the resulting diffs in taste.

What ships

The current system is explicit about what exists now, in working form, without depending on sales language or speculative roadmap copy.

  • Brief compilerTurns intent into a structured spec the eval can actually consume.
  • 28-rule linterFlags recurring failure modes instead of hand-waving them as “subjective”.
  • Eval harnessRuns repeated generations against the same brief for comparison, not anecdotes.
  • Vision-critic scaffoldProvides the review layer structure, ready to plug into live multimodal critique.
  • MCP serverExposes the workflow where model-connected tooling is useful and inspectable.
  • Editor pluginsIn-editor hooks for the working loop rather than a detached demo surface.
  • Eight tokensA small, opinionated base token set for composition, contrast, spacing, and rhythm.

What is gated

Some parts are intentionally marked as dependent on outside infrastructure so the boundary between shipping code and external access stays clean.

  • Live frontier-model callsNeeds API keys.
  • Live vision critiqueNeeds multimodal key + screenshot pipeline.
  • Standalone npm packages for the editor pluginsNeeds packaging and release work beyond the in-repo plugin setup.
  • Additional tokensHeld back until the first set proves necessary rather than decorative.

Read it directly

If the premise matters, the implementation should be inspectable. The repo is the primary call to action because the claim is simple: standards for generated design should be concrete enough to run, critique, and revise in public.
