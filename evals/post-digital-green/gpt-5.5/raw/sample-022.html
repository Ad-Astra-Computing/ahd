Design evals for people who can tell.

AHD turns a design brief into repeatable pressure: rules, runs, screenshots, critique hooks, and tokens that make generated interfaces answer to a standard.

It is for teams that already know the failure mode. The point is not another sermon about bland output. The point is a framework that records what was asked, what was made, what broke, and what can be compared again.

eval-live bash 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

Runs the brief against model specs, captures outputs, and leaves a comparable eval record.

One screen, one claim.

AHD treats generated design as something to inspect, not admire. It makes taste operational enough to review, argue with, and improve without pretending judgement has been automated away.

What ships

  1. brief compiler
  2. 28-rule linter
  3. eval harness
  4. vision-critic scaffold
  5. MCP server
  6. editor plugins
  7. eight tokens

What is gated

  1. live frontier-model calls (needs API keys)
  2. live vision critique (needs multimodal key + screenshot pipeline)
  3. standalone npm packages for the editor plugins
  4. additional tokens
