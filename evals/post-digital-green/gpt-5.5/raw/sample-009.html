Design evaluation for generated interfaces

Artificial Human Design

AHD treats generated design as something to inspect, score, and improve. It turns a brief into runnable checks, then records where an interface holds up: layout, typography, contrast, hierarchy, interaction states, asset honesty, and the small decisions reviewers usually catch by hand.

Premise The point is not another lecture about synthetic sameness. The point is a framework that makes taste review explicit enough to run, discuss, and revise.
eval-live ready 
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
Run a brief against model specs, collect candidates, and review them through the same design constraints every time. Read the code before trusting the claim.

What ships

  • Brief compiler
  • 28-rule linter
  • Eval harness
  • Vision-critic scaffold
  • MCP server
  • Editor plugins
  • Eight tokens

What is gated

  • Live frontier-model calls (needs API keys)
  • Live vision critique (needs multimodal key + screenshot pipeline)
  • Standalone npm packages for the editor plugins
  • Additional tokens

AHD is a working surface for critique. Briefs stay inspectable, rules stay named, and generated outputs become comparable artifacts instead of vibes in a browser tab.
