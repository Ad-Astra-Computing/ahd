<h1>AHD <span>/ Artificial Human Design</span></h1>

<p class="lede">
A framework for evaluating generative design systems against intentional constraints, not statistical likelihood. <strong>You write the brief; the system tests whether the output respects it.</strong> No scoring model trained on Dribbble. No "vibe check." Rules you can inspect, modify, and version.
</p>

<div class="code-block">
<pre><code class="language-bash">ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>
</div>
<p class="code-meta">Run against live models or cached traces. Output: per-sample pass/fail with rule attribution.</p>

<section class="manifest">
<h2>What ships</h2>
<ul>
<li>Brief compiler (YAML/JSON to internal constraint graph)</li>
<li>28-rule linter (typography, layout, color, motion, a11y)</li>
<li>Eval harness (parallel execution, result aggregation, diff reporting)</li>
<li>Vision-critic scaffold (open slot for Multimodal-as-judge)</li>
<li>MCP server (Model Context Protocol for IDE integration)</li>
<li>Editor plugins (VS Code, Zed, Neovim—workspace-local)</li>
<li>Eight tokens (curated, versioned, replaceable)</li>
</ul>
</section>

<section class="manifest">
<h2>What is gated</h2>
<ul>
<li>Live frontier-model calls (needs API keys: OpenAI, Anthropic, Google, etc.)</li>
<li>Live vision critique (needs multimodal key + screenshot pipeline)</li>
<li>Standalone npm packages for the editor plugins (publish pending)</li>
<li>Additional tokens (expansion set, external review in progress)</li>
</ul>
</section>
