AHD — Artificial Human Design
Evaluate design systems before they ship to users

The problem is not AI. The problem is unmeasured output.

Every generated interface claims to be "production-ready." Few are measured against anything stricter than a product manager's patience. AHD is a framework for systematic design evaluation: compile a brief, run it against models you control, and get ranked, critic-scored results you can diff, version, and reject.

It is not a design tool. It is a verification layer—one that treats layout, type, color, and interaction as testable properties, not prompt outputs.

Run the eval

A single command compiles your brief, dispatches to your specified models, and returns scored candidates.

bash 
# eval live against frontier models
$ ahd eval-live swiss-editorial \
    --brief briefs/landing.yml \
    --models <specs> \
    --n 10

Requires ahd CLI and valid API keys for configured providers. Output is JSONL: scores, token usage, and path to each candidate's artifact directory.

Manifest

What ships

  • Brief compiler (YAML/JSON design briefs to structured prompts)
  • 28-rule linter (spacing, type scale, color contrast, motion, duplication detection)
  • Eval harness (parallel dispatch, scoring, ranking, artifact capture)
  • Vision-critic scaffold (pluggable multimodal critique pipeline)
  • MCP server (Model Context Protocol for external tool integration)
  • Editor plugins (VS Code, Zed, Neovim—install from source)
  • Eight foundation tokens (type, color, space, radius, shadow, motion, z-index, breakpoint)

What is gated

Unavailable without external credentials or pending packaging.

  • Live frontier-model calls (needs API keys: OpenAI, Anthropic, Google, or compatible)
  • Live vision critique (needs multimodal key + screenshot pipeline: Playwright/Puppeteer)
  • Standalone npm packages for the editor plugins (pending registry publish)
  • Additional tokens (domain-specific extensions: data viz, e-commerce, editorial)
