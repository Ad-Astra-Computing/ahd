  <header>
    <div class="org">Artificial Human Design</div>
    <h1>A framework for evaluating design<br>through rules, not examples.</h1>
  </header>

  <section>
    <p>Most AI-generated interfaces share the same failure mode: they look plausible because they repeat patterns, not because they satisfy constraints. AHD treats design as a verification problem. You write a brief. The system compiles it to evaluation rules, runs a linter, and scores outputs against those rules—not against a training set.</p>
    <p>The evaluator is one command. The rules are inspectable. The vision critic is swappable. The framework is designed for people who already know what "slop" means and want tooling that assumes responsibility rather than outsourcing it.</p>
  </section>

  <section>
    <h2>What ships</h2>
    <ul class="manifest-list">
      <li>Brief compiler (YAML/JSON → rule tree)</li>
      <li>28-rule linter with violation provenance</li>
      <li>Eval harness with deterministic scoring</li>
      <li>Vision-critic scaffold (bring your own multimodal model)</li>
      <li>MCP server for IDE integration</li>
      <li>Editor plugins (Neovim, VS Code, Zed)</li>
      <li>Eight base tokens (typography, color, spacing, layout, motion, interaction, content, accessibility)</li>
    </ul>
  </section>

  <section class="gated">
    <h2>What is gated</h2>
    <ul class="manifest-list">
      <li>Live frontier-model calls (needs API keys)</li>
      <li>Live vision critique (needs multimodal key + screenshot pipeline)</li>
      <li>Standalone npm packages for the editor plugins</li>
      <li>Additional tokens (domain-specific rule packs)</li>
    </ul>
    <p class="note">Everything gated is source-available in-repo. The gates are operational, not commercial.</p>
  </section>
