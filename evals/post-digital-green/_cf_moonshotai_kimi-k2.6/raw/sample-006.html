/// AHD

A framework for evaluating whether a design was made by a human who understands the problem, or by a model that understood the prompt.

Most AI tooling optimises for throughput. AHD optimises for evidence: structured briefs, rule-based linting, model-agnostic evaluation, and vision critique that checks the rendered output against intent.

It is not a design tool. It is a rigor tool for people who already have opinions about what generative workflows are doing to craft.

bash 
ahd eval-live swiss-editorial \
    --brief briefs/landing.yml \
    --models <specs> \
    --n 10

What ships

  • Brief compiler YAML + constraint resolver
  • 28-rule linter typography, spacing, interaction, colour
  • Eval harness batch runner with scoring and regression
  • Vision-critic scaffold multimodal pipeline structure, local fallback
  • MCP server protocol handler for editor integration
  • Editor plugins Neovim, VS Code; run inline from buffer
  • Eight tokens base vocabulary for rule training and testing

What is gated

  • Live frontier-model calls needs API keys
  • Live vision critique needs multimodal key + screenshot pipeline
  • Standalone npm packages for the editor plugins pending registry setup
  • Additional tokens expansion set, in review
