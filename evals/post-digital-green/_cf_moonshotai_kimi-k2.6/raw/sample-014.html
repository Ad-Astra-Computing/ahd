AHD // Artificial Human Design
Manifest Source

A framework for evaluating design systems with models that do not understand design.

Every AI-generated site looks the same because the evaluation step is missing. AHD provides a compiler, a linter, and a harness for structured critique—so you can run repeatable evals against your own briefs instead of accepting the first output.

bash eval harness
$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10
# Runs 10 generations against the same brief, scores each against 28 rules,
# exits non-zero if any critical rule fires. Vision critique where configured.
Read the code

Built for teams who already run eslint, tsc, or playwright test in CI and want something equivalent for generative design work. No dashboard, no hosted service.

What ships

  • Brief compiler — YAML schema to structured prompt with inheritance
  • 28-rule linter — design-specific rules with severity levels (critical, warn, info)
  • Eval harness — batch runner with scoring, regression detection, exit codes
  • Vision-critic scaffold — pipeline for multimodal critique (render → screenshot → judge)
  • MCP server — exposes eval and lint as Model Context Protocol tools
  • Editor plugins — current support for VS Code and Zed (install from repo)
  • Eight tokens — base set for typography, spacing, color, and layout primitives

What is gated

  • Live frontier-model calls — requires your own API keys (OpenAI, Anthropic, Google, etc.)
  • Live vision critique — requires multimodal key + headless browser screenshot pipeline
  • Standalone npm packages for editor plugins — currently install from source; registry publish pending
  • Additional tokens — extended sets for specific design languages, not yet released

Gated items are blocked on external resources or release scheduling, not paywalls. The core framework is unencumbered.
