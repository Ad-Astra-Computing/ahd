Artificial Human Design

A framework for evaluating design with humans in the loop.

You have already seen the slop. You do not need another essay about it. AHD is a toolchain that encodes design intent, runs structured evals against it, and keeps a human as the final gate.

The problem is not that models generate layouts. The problem is that no one checks whether the layout matches the brief, whether the hierarchy survives translation, whether the tokens hold up across breakpoints.

AHD is the check. It is not a generator. It is a compiler, a linter, and a harness for running design evals at the speed you already work.

bash 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

What ships

  • Brief compiler (YAML → typed design spec)
  • 28-rule linter (typography, spacing, hierarchy, motion)
  • Eval harness (batch runner with deterministic seeding)
  • Vision-critic scaffold (screenshot → structured critique pipeline)
  • MCP server (Model Context Protocol for IDE integration)
  • Editor plugins (VS Code, Zed; vim in review)
  • Eight tokens (curated semantic design primitives)

Everything above runs locally. No API keys required for core evals.

What is gated

  • Live frontier-model calls (needs API keys: OpenAI, Anthropic, Google, or local equivalent)
  • Live vision critique (needs multimodal key + screenshot pipeline)
  • Standalone npm packages for the editor plugins (currently bundled; extracted on request)
  • Additional tokens (eight more in review; gated on community validation)

Gated features are documented and stubbed. You can see exactly where they plug in.

The implementation is open. Read the eval harness, the rule definitions, and the token schema before you adopt.
