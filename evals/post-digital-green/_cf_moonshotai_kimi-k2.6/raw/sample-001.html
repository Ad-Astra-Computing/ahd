AHD — Artificial Human Design

A framework for evaluating design with intention

You have already seen the slop. AHD is not a defense of human designers or a condemnation of tools. It is a practical system for compiling design briefs into evaluable criteria, running them against frontier models with structured critique, and keeping the human in the loop where judgment actually matters.

The eval

Run a brief against multiple models with a standardized harness. The linter enforces 28 rules before anything generates. The vision critic scores what comes back. You read, you decide.

bash 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

# Compiles brief → runs 28-rule linter → generates against model specs
# → vision-critic scores → outputs ranked results with trace

The linter fails hard on malformed briefs. No generation without intent.

Components

What ships

  • Brief compiler — YAML/JSON schema with constraint resolution
  • 28-rule linter — structural validation, no auto-fix
  • Eval harness — parallel runner with trace logging
  • Vision-critic scaffold — multimodal scoring pipeline (local runner)
  • MCP server — Model Context Protocol for external tool integration
  • Editor plugins — VS Code, Zed, Vim (source in repo)
  • Eight tokens — curated design vocabulary for prompt grounding

What is gated

  • Live frontier-model calls — needs API keys, your spend
  • Live vision critique — needs multimodal key + screenshot pipeline setup
  • Standalone npm packages for editor plugins — pending CI migration
  • Additional tokens — under review, quality gate is strict
