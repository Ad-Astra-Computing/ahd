            <div class="wordmark"><span>AHD</span> / Artificial Human Design</div>
            <h1>A design system for distinguishing deliberation from diffusion.</h1>
            <p class="lead">
                Every generative tool ships with the same drift: averages accumulate, intent erodes, taste becomes a lagging indicator. <strong>AHD is a framework for running structured design evaluations against frontier models</strong>—not to automate decisions, but to make the reasoning behind them explicit, testable, and versioned.
            </p>
            <p class="lead">
                You write a brief in YAML. The compiler validates it against 28 rules. The harness generates candidates, scores them through a vision critic, and returns a ranked set with full provenance. The model can be swapped; the criteria stay fixed.
            </p>
        </div>

        <section class="manifest manifest-ships">
            <h2>What ships</h2>
            <ul>
                <li><strong>Brief compiler</strong>
                    <span class="detail">YAML-to-structured-prompt with schema validation and error recovery</span>
                </li>
                <li><strong>28-rule linter</strong>
                    <span class="detail">Static analysis for brief completeness, constraint consistency, and evaluability</span>
                </li>
                <li><strong>Eval harness</strong>
                    <span class="detail">Parallel generation, scoring, and ranking with deterministic seeding</span>
                </li>
                <li><strong>Vision-critic scaffold</strong>
                    <span class="detail">Protocol for multimodal critique; accepts local or remote vision backends</span>
                </li>
                <li><strong>MCP server</strong>
                    <span class="detail">Model Context Protocol implementation for integration with compatible editors</span>
                </li>
                <li><strong>Editor plugins</strong>
                    <span class="detail">VS Code and Vim extensions for inline brief editing and result preview</span>
                </li>
                <li><strong>Eight tokens</strong>
                    <span class="detail">Curated design-taste embeddings for bias detection and candidate filtering</span>
                </li>
            </ul>
        </section>
        
        <section class="manifest manifest-gated">
            <h2>What is gated</h2>
            <ul>
                <li><strong>Live frontier-model calls</strong>
                    <span class="detail">Requires your own API keys (OpenAI, Anthropic, Google, or compatible local endpoint)</span>
                </li>
                <li><strong>Live vision critique</strong>
                    <span class="detail">Requires multimodal key plus configured screenshot pipeline (Playwright, Puppeteer, or manual capture)</span>
                </li>
                <li><strong>Standalone npm packages for the editor plugins</strong>
                    <span class="detail">Pending registry setup; install from source in the interim</span>
                </li>
                <li><strong>Additional tokens</strong>
                    <span class="detail">Twelve embeddings in curation; release gated on community review and licensing clearance</span>
                </li>
            </ul>
        </section>
        
        <section class="elaboration">
            <p>
                <strong>The framework assumes you already distrust averages.</strong> It does not promise taste; it instruments the gap between what you asked for and what the model assumed. The linter catches underspecification before generation. The harness keeps candidates you would have discarded so you can inspect the failure mode. The vision critic scores against your criteria, not against a generic rubric.
            </p>
            <p>
                Everything that runs locally does so without network calls. The gated items are transparent about what they need and why. No feature is described as <em>coming soon</em> without an explicit blocker listed.
            </p>
