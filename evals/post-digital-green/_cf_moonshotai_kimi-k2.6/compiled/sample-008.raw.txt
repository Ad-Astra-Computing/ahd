<!-- rule: copy voice: technical, lowercase by default, terse -->
<h1>AHD</h1>

<p>artificial human design — a framework for evaluating generative design output against written constraints. for teams who have already formed an opinion about ai-generated interfaces and want tooling, not a manifesto.</p>

<div class="diagram" role="img" aria-label="system architecture diagram">
<!-- rule: at least one ASCII diagram -->
  brief.yml        linter (28 rules)        eval harness
      |                  |                       |
      +----------&gt;  compiler  &lt;------------------+
                        |
                        v
                   judge model(s)
                        |
                        v
                 vision-critic (opt)
</div>

<p>a brief is a contract. the compiler checks it. the linter scores the output. the eval harness runs it at scale. the vision-critic checks it against screenshots when you have the pipeline.</p>

<div class="cta-block">
  <!-- rule: link to github labelled as read-the-code CTA -->
  <a href="https://github.com/ahd-org/ahd">read the code</a> — <span class="dim">or mirror on <a href="https://codeberg.org/ahd/ahd">codeberg</a></span>
</div>

<h2>run one eval</h2>

<!-- rule: command rendered in monospace code block with language tag bash -->
<pre><code class="language-bash"><span class="sh-keyword">ahd</span> <span class="sh-keyword">eval-live</span> <span class="sh-arg">swiss-editorial</span> <span class="sh-flag">--brief</span> <span class="sh-val">briefs/landing.yml</span> <span class="sh-flag">--models</span> <span class="sh-brkt">&lt;</span><span class="sh-arg">specs</span><span class="sh-brkt">&gt;</span> <span class="sh-flag">--n</span> <span class="sh-val">10</span></code></pre>

<p>models are specified as <code>provider/name/version</code> or a <code>ahd.models.yml</code> file. the harness runs in parallel, scores each output against the compiled brief, and writes results to <code>./out/&lt;run-id&gt;/</code>.</p>
