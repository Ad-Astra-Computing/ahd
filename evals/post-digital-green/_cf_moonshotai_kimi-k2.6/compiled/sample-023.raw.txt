<!-- rule: one screen of reading, terse technical voice -->
<h1>AHD <span class="dim">//</span> <span class="accent">Artificial Human Design</span><span class="caret"></span></h1>

<p class="dim">framework for evaluating generative design systems against human criteria</p>

<!-- rule: at least one ASCII diagram rendered as text -->
<pre style="border: none; padding-left: 0; padding-right: 0;"><!-- rule: no radii --><code>    INPUT               PROCESS              OUTPUT
   brief.yml  --------&gt;  compiler   --------&gt;  structured spec
      |                    |                      |
      v                    v                      v
   models.spec  ------&gt;  linter    --------&gt;  rule violations
      |                    |                      |
      v                    v                      v
   eval-live  --------&gt;  harness   --------&gt;  scored candidates
      |                    |                      |
      v                    v                      v
   screenshots  ------&gt;  vision-critic  ----&gt;  ranked results</code></pre>

<p>The loop is closed by human judgment, not replaced by it. AHD does not generate layouts. It compiles briefs, enforces constraints, runs comparative evaluation, and surfaces the gap between what was requested and what was produced.</p>

<!-- rule: terminal-aesthetic code block with bash language tag -->
<pre><code class="language-bash">$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>

<p>Runs the full pipeline: compile, lint, generate, score, rank. Replace <code>&lt;specs&gt;</code> with provider/model pairs. Output is JSONL to stdout or structured directory tree with <code>--out</code>.</p>

<hr>

<!-- rule: clearly separated manifest section 'What ships' -->
<h2>What ships</h2>
<ul>
<li>brief compiler (yaml to structured design spec)</li>
<li>28-rule linter (typography, spacing, color, motion, accessibility)</li>
<li>eval harness (parallel generation + scoring against brief)</li>
<li>vision-critic scaffold (screenshot ingestion pipeline, local scoring model)</li>
<li>MCP server (model context protocol for editor integration)</li>
<li>editor plugins (vscode + neovim, inline diagnostics via LSP)</li>
<li>eight tokens (curated design-system seeds with explicit lineage)</li>
</ul>

<!-- rule: clearly separated manifest section 'What is gated' -->
<h2>What is gated</h2>
<ul>
<li>live frontier-model calls (needs API keys: openrouter, anthropic, or openai)</li>
<li>live vision critique (needs multimodal key + screenshot pipeline: playwright or puppeteer)</li>
<li>standalone npm packages for the editor plugins (requires registry publishing)</li>
<li>additional tokens (contribution-reviewed, not auto-generated)</li>
</ul>
