<h1>artificial human design</h1>

<p>a framework for evaluating generative design systems. feed a brief, run a lint suite, compare outputs against human-authored rules. no scoring heuristic that rewards average output. no benchmark that optimises for sameness.</p>

<hr>

<!-- rule: ascii diagram required -->
<div class="ascii-diagram">
<!--
    brief.yml  -->  [compiler]  -->  tokenised spec
                                          |
                                          v
    model api <--  [eval harness]  <--  linter (28 rules)
         |                                  ^
         v                                  |
    output dir  -->  [vision critic]  ------+

    fig: ahd data flow. compiler locks requirements;
         linter checks against token constraints;
         vision critic scores execution, not intent.
-->
<pre style="border: none; background: none; padding: 0; margin: 0;">
    brief.yml  --&gt;  [compiler]  --&gt;  tokenised spec
                                          |
                                          v
    model api &lt;--  [eval harness]  &lt;--  linter (28 rules)
         |                                  ^
         v                                  |
    output dir  --&gt;  [vision critic]  ------+
</pre>
</div>

<p>the eval is one command. run it against your own briefs or use the eight included tokens as baseline constraints.</p>

<!-- rule: bash code block with specified command, language tag bash -->
<pre><code><span class="code-prompt">$ </span><span class="code-cmd">ahd eval-live</span> <span class="code-arg">swiss-editorial</span> <span class="code-flag">--brief</span> <span class="code-arg">briefs/landing.yml</span> <span class="code-flag">--models</span> <span class="code-arg">&lt;specs&gt;</span> <span class="code-flag">--n</span> <span class="code-arg">10</span></code></pre>

<p>the harness returns per-run violations, not star ratings. you decide if tradeoffs are acceptable.</p>

<!-- rule: manifest section 'What ships' with enumerated items -->
<section class="manifest">
<h2>what ships</h2>
<ul>
<li>brief compiler — yaml to locked token spec, rejects ambiguous constraints</li>
<li>28-rule linter — spacing, colour contrast, type scale consistency, forbidden-pattern detection</li>
<li>eval harness — batch runner against ollama, openrouter, or anthropic endpoints</li>
<li>vision-critic scaffold — puppeteer capture + vision-model prompt templates</li>
<li>mcp server — exposes linter and compiler as model-context-protocol tools</li>
<li>editor plugins — vscode extension and neovim lua, inline lint markers</li>
<li>eight tokens — complete design system constraints, cc-by-4.0 licensed</li>
</ul>
</section>

<!-- rule: manifest section 'What is gated' with enumerated items -->
<section class="manifest">
<h2>what is gated</h2>
<ul>
<li>live frontier-model calls — needs your own api keys, no proxy included</li>
<li>live vision critique — needs multimodal key plus screenshot pipeline setup</li>
<li>standalone npm packages for editor plugins — publishing blocked on ci migration</li>
<li>additional tokens — six in draft, pending manual audit against 28-rule suite</li>
</ul>
</section>
