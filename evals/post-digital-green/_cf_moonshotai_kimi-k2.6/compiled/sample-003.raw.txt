  <h1>artificial human design<span class="cursor"></span></h1>
  <!-- rule: dim for secondary info -->
  <p style="color: oklch(0.55 0.05 150);">a framework for evaluating generative design systems against human criteria.</p>
  
  <p>you have seen the slop. the same curve, the same shadow, the same purple gradient. this is not a manifesto against tools — it is a method for forcing rigor into the loop.</p>
  
  <p>AHD compiles briefs, lints output, runs multimodal evals, and keeps a human in the chain. the human does not supervise. the human decides what good means, then the system checks if the machine got there.</p>
  
  <h2>how it works</h2>
  
  <!-- rule: at least one ASCII diagram rendered as text -->
  <div class="diagram">
+--------+     +-----------+     +------------+     +--------+
| brief  | --> | compiler  | --> | 28-rule    | --> | judge  |
|  .yml  |     | (static)  |     | linter     |     | (you)  |
+--------+     +-----------+     +------------+     +--------+
                    |                                    ^
                    v                                    |
               +-----------+                        +---------+
               | eval-live | ---------------------> | scores  |
               | (model)   |                        | + diff  |
               +-----------+                        +---------+
  </div>
  
  <p>the brief is a contract. the linter catches机械重复 before it ships. the eval harness runs the same prompt across models and versions. the vision critic takes a screenshot and compares against spec, not vibe.</p>
  
  <!-- rule: required — bash code block with specific command -->
  <pre><code><span class="comment"># run evaluation against a brief, compare n model outputs</span>
$ <span class="prompt">ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</span></code></pre>
  
  <p>specs are provider:model tuples — openai:gpt-4o, anthropic:claude-sonnet-4-20250514, google:gemini-2.5-pro, etc. the harness handles concurrency, retries, cost tracking, and diff rendering.</p>
  
  <h2>what ships</h2>
  <!-- rule: clearly separated manifest section -->
  <ul>
    <li>brief compiler — validates schema, inlines tokens, expands constraints</li>
    <li>28-rule linter — catches banned patterns, measures entropy, flags repetition</li>
    <li>eval harness — concurrent execution, cost accounting, structured output validation</li>
    <li>vision-critic scaffold — screenshot-to-spec comparison pipeline (local inference)</li>
    <li>MCP server — exposes lint and eval as tools for claude, zed, etc.</li>
    <li>editor plugins — vscode and zed extensions for inline lint and brief preview</li>
    <li>eight tokens — design tokens encoded as typed constraints, not values</li>
  </ul>
  
  <h2>what is gated</h2>
  <!-- rule: clearly separated manifest section -->
  <ul>
    <li>live frontier-model calls — needs API keys and rate-limit handling</li>
    <li>live vision critique — needs multimodal key + screenshot pipeline (playwright/puppeteer)</li>
    <li>standalone npm packages for the editor plugins — still monorepo-only</li>
    <li>additional tokens — locked behind contributor agreement, not paywall</li>
  </ul>
