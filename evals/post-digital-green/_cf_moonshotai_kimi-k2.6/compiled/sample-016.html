artificial human design — v0.1.0

AHD

a framework for evaluating generative design systems. you have seen the slop. this is the audit.

AHD treats design generation as a testable surface. a brief compiles to a finite spec. models run against it. a linter checks the output against rules that do not care where the pixels came from.

the goal is not more ai. the goal is accountable ai: score before ship, inspect before approve.

   BRIEF ----+--> COMPILER ----> SPEC
      |      |       |
      |      |       v
      +------+--> LINTER (28 rules)
                    |
   MODELS <---------+--> EVAL HARNESS
      |                      |
      +------> OUTPUT <------+--> VISION CRITIC
                    |
                    v
               SCORE + TRACE

run one eval:

$ ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

the harness scores all ten runs, keeps traces, and surfaces which rules failed where. read the code.

what ships

  • brief compiler (yaml-to-spec, with constraint validation)
  • 28-rule linter (spacing, hierarchy, colour, motion, accessibility)
  • eval harness (batch runner, trace logger, scorer)
  • vision-critic scaffold (pluggable, with local fallback)
  • mcp server (model context protocol for editor integration)
  • editor plugins (vscode, neovim—simple at first)
  • eight tokens (design-system primitives, cc-by-4.0)

what is gated

  • live frontier-model calls (needs api keys)
  • live vision critique (needs multimodal key + screenshot pipeline)
  • standalone npm packages for the editor plugins
  • additional tokens (beyond the initial eight)

gated items require your own keys and infrastructure. the core runs offline.
