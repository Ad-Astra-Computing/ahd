artificial human design, v0.3.0

ahd

you have seen the slop. thin pastels, three cards, a gradient that wants to be trusted. not a framework for making more. a framework for deciding what to stop making.

ahd compiles a design brief into a structured token. runs the candidate through a 28-rule linter. scores it against a vision critic. no aesthetic vote, no taste consensus. pass or fail on rules you wrote first.

BRIEF ──► COMPILE ──► TOKEN │ ▼ MODEL(s) / | \ ▼ ▼ ▼ RUN 1 RUN 2 ... RUN n \ | / ▼ ▼ ▼ LINTER (28 rules) │ ▼ VISION CRITIC │ ▼ PASS / FAIL 
ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

the command runs live frontier calls. without keys, use ahd eval-static against cached outputs.

what ships

  • brief compiler (yaml / json / toml in, token out)
  • 28-rule linter (spacing, contrast, motion, grid, typography, surface rules)
  • eval harness (batch runner, scorer, reporter)
  • vision-critic scaffold (llava / gpt-4-vision / local clip, pluggable)
  • mcp server (model context protocol, stdio transport)
  • editor plugins (vim, nvim, vscode — inline diagnostics)
  • eight tokens (swiss-editorial, post-digital-green, brutal-minimal, three more, two reserved)

what is gated

  • live frontier-model calls (needs API keys: anthropic, openai, google, or local endpoint)
  • live vision critique (needs multimodal key + screenshot pipeline: puppeteer or playwright)
  • standalone npm packages for the editor plugins (currently bundled, separate registry pending)
  • additional tokens (24 more in draft, gated on community linting)
