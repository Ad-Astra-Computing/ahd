  <header>
    <div class="timestamp">2025-01-13</div>
    <h1>artificial human design</h1>
  </header>

  <p>a framework for evaluating design generated by models. not a tool for generating more. the problem is assumed: you have seen the slop. you want to measure it, constrain it, or exclude it.</p>

  <p>this is for teams who already lint code and want equivalent rigour for their interface layer. briefs are compiled to typed constraints. models are run against those constraints. output is scored, not shipped blindly.</p>

  <!-- rule: required-ascii-diagram -->
  <div class="ascii-diagram">
     BRIEF        MODEL(s)       OUTPUT        SCORE
    --------     ----------     --------      ------
       |             |             |            |
       v             v             v            v
    [compiler] -> [harness] -> [critic] -> [report]
       ^                                        |
       |________langchain/mcp___________________|
  </div>

  <!-- rule: required-command-bash-code-block -->
  <pre><code class="language-bash">ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>

  <p>the command compiles a brief, runs <code>n</code> generations through specified models, and returns a scored matrix. the linter enforces 28 rules derived from actual design systems, not aspirational goals.</p>

  <!-- rule: required-manifest-what-ships -->
  <section class="manifest">
    <h2>what ships</h2>
    <ul>
      <li>brief compiler (yaml-to-constraint tree)</li>
      <li>28-rule linter (spacing, type, colour, motion, surface)</li>
      <li>eval harness (parallel generation + scoring)</li>
      <li>vision-critic scaffold (openai/anthropic-compatible, multimodal)</li>
      <li>MCP server (model context protocol for editor integration)</li>
      <li>editor plugins (vscode, zed, neovim—git submodule for now)</li>
      <li>eight tokens (design-system primitives, CC-BY-4.0)</li>
    </ul>
