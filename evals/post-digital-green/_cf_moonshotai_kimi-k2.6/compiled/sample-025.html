ahd

artificial human design / design evaluation for the slop era

you have seen the output. generated layouts with identical curvature, the same three typefaces, hero gradients that resolve to identical hue angles. you do not need another warning. you need a way to measure whether what ships is deliberate.

ahd is a framework for compiling design briefs, linting output against constraint sets, and running model evaluations with calibrated scoring. it treats "looks human" as a testable property, not a marketing claim.

+-----------+ +-----------+ +-----------+ | brief |--->| linter |--->| eval | | compiler | | 28 rules | | harness | +-----------+ +-----------+ +-----+-----+ | +-----v-----+ | vision | | critic | +-----------+

run one eval

ahd eval-live swiss-editorial --brief briefs/landing.yml --models <specs> --n 10

swiss-editorial is one of eight built-in tokens. pass --dry-run to lint the brief without burning api calls.

what ships

  • brief compiler (yaml/json -> typed constraints)
  • 28-rule linter (alignment, measure, colour gamut, motion policy)
  • eval harness (multi-model, temperature sweep, consensus scoring)
  • vision-critic scaffold (screenshot -> structured critique, no model call)
  • mcp server (stdio transport, exposes compiler + linter)
  • editor plugins (vim, vscode: syntax highlight, lint on save)
  • eight tokens (design briefs as versioned artifacts: swiss-editorial, brutalist-system, post-digital-green, militant-minimal, thermal-paper, tts-terminal, civic-webring, nocturnal-manuscript)

what is gated

  • live frontier-model calls (needs api keys: openrouter, anthropic, openai, or local ollama endpoint)
  • live vision critique (needs multimodal key + screenshot pipeline: playwright, puppeteer, or manual capture)
  • standalone npm packages for the editor plugins (currently bundled; separate release gated on ci migration)
  • additional tokens (briefs in draft: three at prototype stage, gated on peer review)
