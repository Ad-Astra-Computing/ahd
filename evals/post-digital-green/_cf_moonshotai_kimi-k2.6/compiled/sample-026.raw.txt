<h1>ahd<span class="amber">.</span></h1>
<p class="dim">artificial human design — a framework for evaluating generative interfaces</p>
</header>

<hr>

<p>you have seen the slop. thin praise, overconfident spacing, the uncanny sheen of prompts iterated to death. ahd does not sell you on the problem. it gives you the rigour to measure it.</p>

<p>the framework compiles briefs into structured evals, runs models against pinned rule-sets, and scores outputs on design intent rather than polish. a vision-critic scaffold compares renders to spec. an MCP server surfaces results in your editor. everything is versioned, inspectable, and deliberately constrained.</p>

<div class="ascii-diagram">

brief.yml ──┬──> compiler ──> linter ──┬──> eval harness ──> report
            │     (28 rules)           │
            │                          └──> vision-critic ──> diff
            │
            └──> tokens ──> prompt scaffold ──> model call
</pre>
</div>

<!-- rule: terminal-aesthetic code block per brief -->
<!-- rule: bash language tag per required -->
<pre><code class="language-bash">ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>

<p>the harness runs ten generations against the same brief, checks each against the compiled rule-set, and emits a json trace you can diff, replay, or version.</p>

<!-- rule: clearly separated manifest section 'What ships' per required -->
<section class="manifest">
<h2>what ships</h2>
<ul>
<li>brief compiler — yaml to structured eval plan</li>
<li>28-rule linter — spacing, hierarchy, type scale, colour contrast, motion policy</li>
<li>eval harness — parallel generation, result capture, trace export</li>
<li>vision-critic scaffold — screenshot pipeline, perceptual diff, rule overlay</li>
<li>MCP server — model context protocol for editor integration</li>
<li>editor plugins — vscode and neovim bindings (source-distributed, not yet packaged)</li>
<li>eight tokens — curated design-system seeds with full provenance</li>
</ul>
</section>

<!-- rule: clearly separated manifest section 'What is gated' per required -->
<section class="manifest">
<h2>what is gated</h2>

<li>standalone npm packages for the editor plugins — pending registry and CI</li>
<li>additional tokens — gated on curation and legal review</li>
</ul>
