<header>
  <h1>artificial human design</h1>
  <p class="dim">a framework for evaluating generative design output without pretending it is human-made</p>
</header>

<main>

<p>you have seen the slop. the same gradients, the same three cards, the same "build the future of" headline rewritten by a model that has read every other landing page. you do not need another lecture on why this is bad. you need a way to measure whether what ships is deliberate.</p>

<p>AHD is a compiler, a linter, and an eval harness for design briefs. you write constraints. the system generates candidates, scores them against those constraints, and surfaces the failures. the human decides what ships.</p>

<div class="cta-block">
  <a href="https://github.com/artificialhumandesign/ahd">read the code →</a> <!-- rule: link to github labelled as read-the-code CTA -->
</div>

<h2>run an eval</h2>

<pre><code class="language-bash">ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre> <!-- rule: command rendered in monospace code block with language tag bash -->

<p class="dim">outputs a scored matrix. failures are explicit. no "vibe" metric.</p>

<section class="manifest">
  <h2>what ships</h2>
  <ul>
    <li>brief compiler — structured constraint definition from yaml</li>
    <li>28-rule linter — spacing, measure, contrast, motion policy, forbidden pattern detection</li>
    <li>eval harness — batch runner with deterministic seeding, scoring matrix output</li>
    <li>vision-critic scaffold — rule-based image analysis pipeline (local models)</li>
    <li>MCP server — model context protocol for editor integration</li>
    <li>editor plugins — vscode, zed, neovim (submodule builds, not standalone)</li>
    <li>eight tokens — base set covering type, colour, grid, surface, motion, forbidden, required, voice</li>
  </ul>
</section> <!-- rule: What ships manifest section -->

<section class="manifest">
