<h1>artificial human design</h1>

<p class="rule">framework for evaluating design output against human standards</p>

<p>
you have seen the slop. thin gradients, rounded everything, markdown in pill
shapes, three cards in a row with identical icons. you do not need the lecture.
this is a toolset for deciding whether generated work meets a bar before it
ships.
</p>

<div class="ascii-diagram">
<!-- rule: at least one ASCII diagram rendered as text -->
  BRIEF ──► COMPILE ──► LINT(28) ──► GENERATE ──► EVAL ──► CRITIQUE
    │                                                    │
    └─────────────────────LOOP◄──────────────────────────┘
</div>

<p>
ahd is a brief compiler, a linter, an eval harness, and a vision critic.
it runs models against constraints you define, then scores the output.
the thesis: constrain first, generate second, evaluate always.
</p>

<h2>run the eval</h2>

<!-- rule: command in monospace code block with bash language tag -->
<pre><code>ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>

<p>
this loads the brief, compiles to system prompts, runs ten generations across
specified models, and scores each against the brief's rule set. results are
structured for programmatic comparison or human review.
</p>

<h2>what ships</h2>
<!-- rule: clearly separated manifest section 'What ships' -->
<div class="manifest-block">
<div class="manifest-title ships">what ships</div>
<ul>
<li>brief compiler (yml / json schema to structured prompts)</li>
<li>28-rule linter (spatial, typographic, colour, motion constraints)</li>
<li>eval harness (multi-model batch runner with structured output)</li>
<li>vision-critic scaffold (screenshot-to-verdict pipeline, local)</li>
<li>MCP server (model context protocol for editor integration)</li>
<li>editor plugins (vscode, neovim, zed — bundled in repo)</li>
<li>eight tokens ( curated design-direction primitives, CC-BY-4.0 )</li>
</ul>
</div>

<!-- rule: clearly separated manifest section 'What is gated' -->
<div class="manifest-block">
<div class="manifest-title gated">what is gated</div>
<ul>
<li>live frontier-model calls (needs API keys: openai, anthropic, google, etc)</li>
<li>live vision critique (needs multimodal key + screenshot pipeline)</li>
<li>standalone npm packages for the editor plugins (packaging backlog)</li>
<li>additional tokens (requires curation cycle, not yet released)</li>
</ul>
</div>

<h2>how it differs</h2>
<p>
most "AI design" tools optimize for speed of output. ahd optimizes for
confidence in evaluation. the generator is the commodity. the constraint
surface and the scoring rubric are where value lives. we do not sell tokens,
models, or hosting. we ship a framework for saying no.
</p>
