<h1>ahd</h1>

<p>you have seen the slop. thin gradients, rounded everything, three cards in a row, a testimonial from "sarah, pm" with a generic avatar. the suspicion that generative tools flatten taste into a single acceptable median. this is the problem ahd was built to address, not by lecture, but by tooling.</p>

<p>ahd is an evaluation and linting framework for interface generation. it compiles structured briefs, runs models against them, and scores outputs against human-curated rules. the thesis: generated design can be held to a standard, and that standard can be automated.</p>

<div class="ascii-diagram">
+--------+    +-------------+    +----------------+    +-------+
| brief  | -> |  compiler   | -> | frontier model | -> | score |
|  .yml  |    |  + linter   |    | (or local llm) |    |  /10  |
+--------+    +-------------+    +----------------+    +-------+
                   ^                      |
                   |              +-------+-------+
                   +-------------+ vision critic |
                                  | (multimodal)  |
                                  +---------------+
</div>

<p>the eval loop is one command. no local dependencies beyond node 20+ and a key.</p>

<pre><code><span class="comment"># run live eval against a brief, compare n variants</span>
ahd eval-live swiss-editorial --brief briefs/landing.yml --models &lt;specs&gt; --n 10</code></pre>

<p>the linter runs 28 rules covering alignment, colour contrast, type scale consistency, motion policy enforcement, and forbidden-pattern detection. the vision-critic scaffold accepts screenshots and returns structured critique, gated on multimodal api access. the mcp server exposes the toolchain to editors that speak the protocol.</p>

<p><a href="https://github.com/artificialhumandesign/ahd">read the code →</a></p>

<section class="manifest">
<h2>What ships</h2>
<ul>
<li>brief compiler — yaml-to-prompt with variable interpolation and constraint validation</li>
<li>28-rule linter — static analysis for generated html/css, no model calls required</li>
<li>eval harness — parallel execution, scoring aggregation, result export to ndjson</li>
<li>vision-critic scaffold — image input, structured critique output, pluggable model backend</li>
<li>mcp server — model context protocol implementation for editor integration</li>
<li>editor plugins — lsp-compatible diagnostics for vscode and neovim (editor-side scripts, not standalone packages)</li>
<li>eight tokens — curated design vocabularies: post-digital-green, brutalist-concrete, swiss-editorial, terminal-amber, lo-fi-zine, critical-engineering, soft-minimal, civic-systems</li>
</ul>
</section>

<section class="manifest manifest-gated">
<h2>What is gated</h2>
<ul>
<li>live frontier-model calls — needs api keys (openrouter, anthropic, openai, or ollama for local)</li>
<li>live vision critique — needs multimodal key + screenshot pipeline (playwright, puppeteer, or manual capture)</li>
<li>standalone npm packages for the editor plugins — currently vendored scripts; packaging pending registry setup</li>
<li>additional tokens — two in draft, gated on community contribution and review</li>
</ul>
</section>
