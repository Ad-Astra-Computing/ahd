<header>
<h1>artificial human design<span class="caret"></span></h1>
<p>a framework for evaluating generative design output against explicit constraints, not vibe thresholds.</p>
</header>

<hr>

<p>you have seen the slop. gradient text that says "ai", three identical feature cards, a centred hero with a pill badge and two ctas. you do not need another lecture on why this is bad. you need a tool that checks for it.</p>

<p>ahd compiles a brief into a concrete evaluation. run models against the spec. score the output. ship what passes, reject what does not.</p>

<section class="manifest">
<h2>what ships</h2>
<ul>
<li>brief compiler — yaml/structured text to executable constraint set</li>
<li>28-rule linter — detects gradients, sans-serif body, rounded corners, emoji bullets, shimmer, blobs, and 22 other failure modes</li>
<li>eval harness — parallel runner for n model outputs with structured scoring</li>
<li>vision-critic scaffold — screenshot-to-verdict pipeline (model-agnostic, key not required for scaffold)</li>
<li>mcp server — exposes eval context to external editors and agents</li>
<li>editor plugins — vscode and neovim bindings for inline brief validation</li>
<li>eight tokens — starting set of design-system seeds (cc-by-4.0)</li>
</ul>
</section>

<section class="manifest">
<h2>what is gated</h2>
<ul>
<li>live frontier-model calls — needs your own api keys (openai, anthropic, google, etc)</li>
<li>live vision critique — needs multimodal key + screenshot pipeline (playwright or puppeteer)</li>
<li>standalone npm packages for the editor plugins — currently bundled; separate publish pending</li>
<li>additional tokens — eight now, more gated on community contribution</li>
</ul>
</section>
